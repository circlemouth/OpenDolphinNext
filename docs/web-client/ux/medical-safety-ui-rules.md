# Medical Safety UI Rules

## 1. 目的

この文書は、OpenDolphinNext Web Client の医療安全UI仕様を定義する。

DADSの原則である、アクセシビリティ、一貫性、重要情報を隠さないこと、フォームでplaceholderやdisabledに依存しないことを、電子カルテ向けに具体化する。

GUI 改修前の残件棚卸しと後工程 backlog は [../../validation/gui-remediation-handoff.md](../../validation/gui-remediation-handoff.md) を参照する。この backlog は未完項目の引き渡しであり、current contract の達成済み事実や release-ready 判定ではない。

## 2. 患者識別

主要画面では患者ヘッダーを常時表示する。

表示する項目:

- 患者番号
- 氏名
- 生年月日
- 性別
- 年齢
- 受付日
- 診療科
- 担当医
- 保険組合せ
- ORCA受付ID
- ORCA由来情報の取得日時

## 3. 重大操作確認

次の操作では確認モーダルを出す。

- 診療録確定
- 診療録訂正
- 診療録取消
- 処方確定
- 処方変更
- 処方中止
- 処方取消
- ORCA送信
- ORCA再送
- 診察終了
- 会計送信

確認モーダルには患者識別情報を再掲する。

最低限、次を同一 alertdialog 内に表示する。

- 患者番号
- 氏名
- 生年月日
- 性別
- 年齢
- 受付日
- 診療科
- 担当医
- 保険組合せ
- ORCA受付ID

## 4. ORCA警告・不一致

次を隠してはならない。

- ORCA警告
- ORCAエラー
- ORCA不一致
- ORCA側のみ存在する情報
- ORCA送信失敗
- UNKNOWN
- 要確認
- 保留

重要情報はaccordion、details、disclosureの中だけに隠してはならない。

## 5. フォーム

フォームは以下を守る。

- label必須
- 必須 / 任意を明示
- support textは、入力条件、単位、禁忌、送信不可理由、復旧操作など、判断や安全に必要な場合だけ置く
- placeholderで説明を代用しない
- エラーは具体的に書く
- disabledを安易に使わない
- disabledを使う場合は理由と有効化条件を近くに表示する
- 入力変更だけで突然送信、画面遷移、ダイアログ表示をしない

主要医療安全画面の placeholder / native disabled は `web-client/scripts/verify-medical-safety-ui-copy.mjs` で既存残件数を cap として固定する。新規追加は、説明をラベルまたはサポートテキストへ移す、または `aria-disabled` と近傍理由/有効化条件へ置き換えるまで受け入れない。

### 5.1 常時表示する説明文の制限

DADS の「重要情報を隠さない」「placeholder に依存しない」は、通常状態の説明文を常時並べることを意味しない。
電子カルテ画面では、視線誘導を診療上の判断、未入力、警告、送信可否、患者識別へ集中させる。

常時表示してよい文言:

- 未入力、必須不足、形式不正、禁忌、相互作用、ORCA警告、UNKNOWN、送信不可など、操作者が今判断する必要のある状態
- disabled / aria-disabled の理由と解除条件
- 単位、上限、日数、投与経路など、誤入力防止に直結する短い条件
- 重大操作前の患者識別、対象、影響範囲、確定ではないことの明示

常時表示しない文言:

- 空状態の一般説明。例: 「当日のオーダーはありません。必要な分野から追加してください。」
- 画面構成の説明。例: 「この列で編集します」「左に過去カルテ、右にオーダー情報をまとめます。」
- すでに UI から分かる操作説明。例: 「編集はボタンで切り替えます。」
- 正常時の安心表示。例: 「安全チェックで検出できる候補はありません。」
- 教育的な原則説明。例: 「1 RP = 共通用法。異なる用法は別RP。」

これらが必要な場合は、初回オンボーディング、ヘルプ、ツールチップ、details、または screen reader 向け補足へ退避し、業務画面の通常視線には置かない。退避しても、警告、エラー、必須不足、UNKNOWN、患者取り違え防止情報は隠してはならない。

## 6. ボタン

- primary actionは原則1画面1つ
- 戻る、取消、中止と、送信、確定、完了の位置を一貫させる
- 押下領域を確保する
- 色だけで優先度を表現しない
- 破壊的操作は通常操作と視覚的に区別する

## 7. アクセシビリティ

以下を確認する。

- キーボード操作
- focus表示
- コントラスト
- スクリーンリーダーでの読み順
- モーダルのfocus trap
- エラー箇所への到達性
- ボタン押下領域
- 色だけに依存しない状態表示

## 8. エラー表示

「失敗しました」だけで終わらせない。

エラー表示には可能な限り次を含める。

- 何が起きたか
- 操作者が次に取るべき行動
- ORCA側確認が必要か
- 再送してよいか
- 患者・受付・診療日の確認導線
- 監査ログまたは問い合わせ用の相関ID

## 9. UNKNOWN表示

UNKNOWN状態は、警告バナーまたは同等の強い表示で初期表示する。

表示内容:

- UNKNOWNは成功ではないこと
- 最終送信日時
- 対象API
- 対象患者
- 対象受付
- 再取得・照合・手動確認の導線

## 10. レビュー時の危険シグナル

- placeholderが説明の主役になっている
- disabled理由が近くにない
- ORCA警告がdetails内にだけある
- 患者識別情報なしで確定・送信できる
- 入力変更だけでORCA送信が走る
- モーダルで患者番号・氏名・生年月日が再掲されない
- エラー表示が「失敗しました」だけ
