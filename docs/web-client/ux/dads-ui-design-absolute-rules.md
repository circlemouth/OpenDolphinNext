## 位置づけ

この文書は、`web-client` の UI デザインに関する current policy です。  
既存の画面実装、過去メモ、参考用ガイドラインより優先します。  
矛盾がある場合は、この文書を正本とし、既存実装に引きずられず是正方向で判断します。

この文書の目的は、DADS の内容をそのまま再掲することではなく、`web-client` で迷わず使える絶対ルールに整理することです。

## 絶対ルール

### 1. アクセシビリティを後付けにしない

- 通常文字のコントラストは `4.5:1` 以上、入力枠線や選択状態など非テキスト識別要素は `3:1` 以上を必須とする
- キーボード操作時の `:focus-visible` を必ず可視化する
- 状態差分を色だけで表現しない。文字、下線、枠線、アイコンのいずれかを併用する
- クリックまたはタップ対象は、実質的に `44 x 44` CSS px 以上を確保する

### 2. 重要情報を隠さない

- 重要な説明、警告、操作結果、次に取るべき行動は初期表示で見える位置に置く
- アコーディオンやディスクロージャーは補足情報だけに使い、理解に必須の内容を閉じ込めない
- ノティフィケーションは色だけに依存せず、見出しまたは意味テキストを併記する

### 3. 画面ごとにルールを変えない

- 色、余白、角丸、影、ボタン優先度、リンク状態、アイコンの役割はサービス全体で統一する
- ページ固有の一時しのぎの値を増やさず、既存トークンへ寄せる
- 新しい見た目ルールを追加する場合は、局所最適ではなく全体適用できるかを先に判断する

### 4. フォームは入力負荷より完了率を優先する

- ラベルは必須とし、プレースホルダーで代用しない
- サポートテキストは入力前に読める位置へ置く
- エラー文言は「何が悪いか」と「どう直すか」を具体的に書く
- `disabled`、`readonly`、`maxlength` は安易に使わない
- 入力値変更だけで突然ダイアログ表示や画面遷移を起こさない
- 文字種制限は原則避け、必要なら送信時に正規化または明示的エラーで扱う

### 5. ボタンは優先度と並び順で判断する

- プライマリーは 1 画面 1 個を原則とする
- セカンダリーは同一文脈で多くても 3 個までに抑える
- 進む操作は右、戻るまたは中止は左を基本とし、モバイルでも意味順を維持する
- 強調は塗り、次点はアウトライン、補助はテキストを基本とする
- 無効化より、押した後に不足条件を説明する設計を優先する

### 6. レイアウトは情報の流れを優先する

- 768px 未満をモバイル・タブレット、768px 以上をデスクトップの基本分岐とする
- グリッド、ガター、余白段階を固定し、場当たり的な列幅を増やさない
- 同種要素の間隔は揃え、情報階層が高いほど余白を大きくする
- 画面内で最重要の情報と操作が、視線移動なしに把握できる配置を優先する

### 7. 未整備領域で独自仕様を先走らない

- DADS 側で詳細ガイドラインが未整備の部品は、独自の共通ルールを増やさない
- モーダル、タブ、ステップナビゲーション、プログレス表示などを刷新する場合は、個別仕様で理由と振る舞いを明記する

## `web-client` での実装判断

### タイポグラフィ

- 本文と通常 UI は `16px` を基本とする
- `14px` はテーブルや高密度管理 UI など、領域制約が強い場所に限定する
- 本文行間は原則 `1.5` 以上とする

### 余白

- ベースユニットは `8px` とし、主要段階は `8 / 24 / 64` を起点に設計する
- 局所調整が必要な場合も、既存段階へ丸めてから使う

### 角丸と影

- 角丸と影は component ごとに増殖させず、サービス共通スケールへ寄せる
- 浮遊要素は影だけでなく境界線でも分離を示す
- エレベーションは必要箇所だけに限定し、カード全般を浮かせない

### リンクとナビゲーション

- リンクは下線または同等の視覚手掛かりを持たせる
- 未訪問と訪問済みは見分けられるようにする
- モバイルメニューは 2 階層を超えない
- ボトムナビゲーションは非推奨とする

### フォーム部品

- 日付入力で既知日付を入れさせる場合、カレンダー起点にしない
- メールアドレスを分割入力しない
- コピーアンドペーストを禁止しない
- `aria-live` や `role="alert"` は読み上げ強制のために乱用しない

## 運用ルール

- UI 変更を行う前に、この文書と [web-client-ui-guideline.md](./web-client-ui-guideline.md) の両方を確認する
- 仕様判断で迷ったら、まずこの文書に適合するかを確認し、その後に既存画面との整合を取る
- 既存画面がこの文書に反している場合、新規実装で追従せず、是正方向で設計する
- デザインレビューでは、コントラスト、フォーカス、操作優先度、フォーム負荷、情報の可視性を必須チェック項目にする
