## Threat Model

- Assets: chart revision JSON/CSV export, ORCA report/PDF-like report material, patient images, legacy attachments/images, document attachment references, reviewer evidence.
- Trust boundaries: browser state and request payloads are untrusted; facility, patient/chart/document/attachment ownership, storage metadata, and operation capabilities must be resolved server-side.
- Attack surface: export/download routes, ORCA report creation/staging route, patient image upload/list/download, document create/update/delete with attachment references, legacy attachment/image reads.

## Misuse Cases

1. A caller sends another `facilityId`, owner, role, storage URI, digest, or object key to export another facility's chart/image/report.
2. A user with read-only UI access calls a binary/report/download route directly to bypass an operation-specific export/download capability.
3. A reviewer packet or closeout report copies raw ORCA XML, report body, HAR, trace, screenshot, raw storage path, or patient/insurance detail.
4. A document update submits attachment metadata for a different asset and relies on reference removal to hard-delete the underlying object.
