## Checklist Item

- 16.4 DB障害時読み取り専用モード: patient image upload を監査ログ書き込み不可時に fail-closed にする。

## Threat Model

- 監査ログDBまたは hash chain head が unavailable のまま、患者画像の外部保存準備と添付メタデータ永続化が進み、真正性・追跡可能性・削除追跡が欠落する。
- multipart payload の解析や一時ファイル生成後に失敗すると、DB degraded 中でも攻撃面と作業量が増える。
- エラー応答に DB 詳細、内部パス、患者詳細、raw multipart、storage key、digest を出さない。

## Changes

- `PatientImagesResource.upload` の入口で feature/storage check 後、patient / multipart / storage / DB write に進む前に `AuthoritativeAuditRepository.isWritePathAvailable()` を確認する。
- audit write path が利用できない場合は `audit_log_write_unavailable` / HTTP 503 / `retryable=true` の sanitized response で停止する。
- `PatientImagesResourceTest` に multipart 解析前 fail-closed regression を追加した。
- checklist に patient image upload の read-only guard 完了項目を追記した。
