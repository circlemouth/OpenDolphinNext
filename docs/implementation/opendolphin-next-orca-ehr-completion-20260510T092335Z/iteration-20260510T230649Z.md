## Implementation
- Added `orcaBillingCache` to sanitized `/api/health/readiness` checks.
- The check verifies only schema availability for `orca_billing_cache` and `orca_report_snapshot`.
- Missing schema or query failure returns `status=DOWN` / `reasonCode=orca_billing_cache_unavailable` and makes overall readiness `DOWN`.
- Updated health endpoint contract and Worker D iteration/checklist docs.

## Threats / Mitigations
- Misuse case 1: ORCA is reachable but billing/report cache tables are missing after migration drift, causing unverifiable billing/report display. Mitigation: readiness fails closed via `orcaBillingCache`.
- Misuse case 2: Anonymous readiness leaks SQL, table internals, stack traces, connection details, or raw exception messages. Mitigation: response is limited to fixed component key, `status`, and fixed `reasonCode`.
- Misuse case 3: Operators proceed with ORCA billing/report workflows during DB restore before cache/snapshot schema is available. Mitigation: overall readiness is `DOWN` until both cache/snapshot tables are present.
