## Scope

- Assets: locked `chart_revision`, new amendment/addendum revision rows, `chart_revision_event`, chart export contract.
- Trust boundary: client-provided reason, actor, title, and content are untrusted until server validation. Existing locked revision content is not mutated.
- Attack surface: reasonless correction/cancel, event spoofing against DRAFT or wrong chart, physical overwrite/delete of original chart text, and leaking raw PHI or credentials in summaries/export.

## Misuse Cases

1. A client calls amend/addendum/cancel without a reason or actor.
2. A client targets a DRAFT revision or a revision under another chart/facility.
3. A client attempts to use amend/cancel as a physical overwrite or delete of the finalized source revision.

## Implementation

- Added `POST /api/charts/{chartId}/revisions/{revisionId}/amend`.
- Added `POST /api/charts/{chartId}/revisions/{revisionId}/addendum`.
- Added `POST /api/charts/{chartId}/revisions/{revisionId}/cancel`.
- Added `ChartRevisionChangeRequest` / `ChartRevisionChangeResponse`.
- Added service logic requiring actor and reason, rejecting DRAFT targets, preserving the source revision, and writing before/after summaries.
- Amend/addendum create new `AMENDED` / `ADDENDUM` revisions with server-side content hash and event linkage.
- Cancel records a `CANCELLED` event without deleting or rewriting the source revision.
- Updated document integrity contract with chart export inclusion requirements for revision history.
