## Threat Model

- Assets: reporting PDF payload, report summary section, chart revision provenance, prescription event history, ORCA operation/transmission/reconciliation history.
- Trust boundaries: API caller-provided reporting payload, server-side chart export DTOs, ORCA-derived ledger summaries, PDF template rendering.
- Attack surface: `/reporting/karte` payload fields, summary maps, PDF summary rendering, downstream reviewer packet text extraction.

Misuse cases:

1. Caller includes raw ORCA body, Authorization/Cookie, or XML in reason/summary fields and expects it to appear in PDF output.
2. Caller includes patient name, insurance details, idempotency key, request/response body, or arbitrary nested JSON in summary maps.
3. Caller sends formula-like status/reason text or markup-like XML; reporting must treat it as plain sanitized text.
4. Prescription/ORCA history is present in JSON/CSV export but missing from PDF/reporting, creating provenance mismatch.
