## Queue
- Worker B B-08a: chart revision event append-only DB guard while B-08 full snapshot integration remains blocked on Worker A/C/D contracts.

## Assets / trust boundary / attack surface
- Assets: `chart_revision_event` reason, actor, before/after summary, event hash, revision chain history.
- Trust boundary: API/service callers and direct DB clients can attempt UPDATE / DELETE; inserted events are authoritative history.
- Attack surface: event reason rewrite, before/after summary substitution, event deletion to hide amend/addendum/cancel/finalize history.

## Misuse cases
- A direct DB caller rewrites an amend/cancel reason after export.
- A caller deletes a cancel event to make a cancelled chart appear clean.
- A caller changes before/after summary or event hash to forge a different revision history.

## Implementation
- Added migration `V0322__chart_revision_event_append_only.sql`.
- Added `trg_chart_revision_event_append_only` and `reject_chart_revision_event_rewrite()` to reject UPDATE / DELETE with `chart_revision_event_append_only`.
- Extended `ChartRevisionFinalizedWriteGuardSchemaTest` to insert a FINALIZED event and assert both UPDATE and DELETE are rejected.
- Updated fresh schema expected migration version to `0322`.
