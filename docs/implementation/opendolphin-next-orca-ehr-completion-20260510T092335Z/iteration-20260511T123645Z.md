## Assets / trust boundary / attack surface
- Assets: chart revision export hash, revision/event history, snapshot manifest references/hashes, prescription event history, ORCA operation/transmission/reconciliation history, PDF report bytes, patient name/birth date required for the report header.
- Trust boundary: HTTP request and browser payload are untrusted. Facility, chart ownership, patient reference, and reporting payload are derived from server session and DB state.
- Attack surface: guessed `chartId` cross-facility PDF export, PDF-only provenance drift from JSON/CSV, raw ORCA/credential/PHI leakage through reason/summary fields, patient master mismatch, and arbitrary client-provided reporting payload injection.

## Misuse cases
1. Caller from facility B requests facility A chart PDF by guessing `chartId`.
   - Mitigation: `ChartRevisionExportService` reuses the same `chart_document.facility_id` check as JSON/CSV export.
2. Reason or summary fields contain `Authorization`, Cookie, raw XML, SOAP, or arbitrary nested sensitive keys.
   - Mitigation: PDF payload is built from the already sanitized export projection; summary maps remain allowlisted and reason text is redacted before rendering.
3. Chart document points to a missing or cross-facility patient row.
   - Mitigation: PDF payload generation rejects missing/cross-facility patient references with 409 fail-closed.
4. Client tries to submit a custom reporting payload omitting events or injecting untrusted summary fields.
   - Mitigation: `/revisions/export.pdf` accepts no body and constructs `ReportingPayload` server-side from DB/export projection only.
