## Assets And Trust Boundary

- Assets: ready dry-run `qa/billing-report-live-profile/summary.sanitized.json`, manual approval reference, live billing/report evidence plan, `orca_billing_cache`, `orca_report_snapshot`.
- Trust boundary: handoff evidence is not live ORCA success. It authorizes only a human-approved next validation attempt and stores hashes/sanitized policy fields, not approval text, patient identifiers, invoice numbers, `Data_Id`, `Medical_Uid`, storage keys, credentials, or raw artifacts.
- Attack surface: CLI flags, artifact capture environment variables, stale or non-ready dry-run summary, raw identifiers accidentally passed into live handoff, approval reference leakage.

## Misuse Cases And Mitigations

- Misuse case: operator skips exact dry-run readiness and starts live billing/report validation. Mitigation: handoff requires a ready dry-run summary with the billing/report dry-run contract.
- Misuse case: approval ticket or patient/billing identifiers leak into tracked evidence. Mitigation: approval reference is hashed and dry-run patient identity remains hashed; CLI rejects raw identifier flags.
- Misuse case: HAR/trace/video/screenshot/raw network capture is enabled during handoff. Mitigation: handoff rejects capture flags and capture environment variables before any live traffic.
- Misuse case: handoff evidence is treated as paid/receipt/report source-of-truth. Mitigation: summary and docs state it is only a human-approved next live validation attempt and not live success or accounting authority.
