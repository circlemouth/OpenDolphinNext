## Assets / Trust Boundary / Attack Surface

- Assets: patient identity display, Mobile Images upload/lookup UI, router state encounter context, patient image list/upload calls, current UI contract.
- Trust boundary: browser route state and query/deep-link values are not authoritative. They are display context only; upload authorization and image persistence remain server-side responsibilities.
- Attack surface: stale or tampered encounter context in router state, missing patient context, accidental PHI/ORCA identifier leakage into URL/storage/logs, false wording that image upload or ORCA sync is complete.

## Misuse Cases

1. A user opens Mobile Images with a forged `encounter` state containing a different department/insurance and treats it as server authority.
   - Countermeasure: label ORCA acquisition as `遷移文脈 / unverified`; do not send encounter fields to upload APIs.
2. A patient ID arrives through query/deep-link without encounter context and the UI hides missing safety context.
   - Countermeasure: existing missing-patient guard remains, and the header only shows encounter safety fields when present.
3. An upload success is mistaken for ORCA synchronization or chart finalization.
   - Countermeasure: copy and docs explicitly keep Mobile Images upload/lookup separate from ORCA sync and mark context unverified.
4. Sensitive ORCA response bodies or credentials are recorded in tests/docs.
   - Countermeasure: only synthetic IDs/codes are used in tests; no raw ORCA body, credentials, HAR, trace, video, screenshot, or PHI are added.
