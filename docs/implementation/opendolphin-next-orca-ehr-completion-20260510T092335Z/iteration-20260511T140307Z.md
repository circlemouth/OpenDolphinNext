## Pre-implementation model

- Assets: WebORCA Trial candidate discovery summaries, exact selected-candidate readonly preflight gate, backend session login, sanitized candidate rows, and mutation prohibition evidence.
- Trust boundary: candidate discovery is read-only diagnostic evidence; Trial ORCA, local backend, and browser UI are outside the script's authority; candidate proposals cannot authorize mutation.
- Attack surface: raw network/request evidence retention, stale UI locator causing false readiness blockers, per-candidate slowness hiding partial results, and timeout summaries being mistaken for exact preflight.

## Misuse cases

1. A global discovery timeout writes an empty summary and hides which candidate/readiness axis was slow.
2. A rejected server-side candidate still runs slow UI selector probes and exhausts the heartbeat before exact preflight can be attempted.
3. Browser/request diagnostics are retained under `network/*.json` during sanitized evidence mode and later copied into tracked evidence.
4. A partial timeout proposal is treated as Phase 3 mutation authorization without exact selected-candidate readonly preflight.
