## Trust Boundary
- Temporary reconcile may only use sanitized, server-derived billing snapshots.
- Request body, client-provided identifiers, and old snapshots without authority metadata are not trusted.
- Snapshot metadata must show raw-sensitive fields were excluded and server-derived authority is required.

## Attack Surface
- A legacy snapshot without raw-sensitive exclusion metadata being used as recovery authority.
- A snapshot marked as client-provided identifiers trusted being used for ORCA read-only reconcile.
- A snapshot without server-derived authority metadata reaching ORCA transport.
- Raw ORCA body, patient details, insurance details, or credentials entering tracked evidence.

## Misuse Cases
1. A snapshot missing `rawSensitiveFieldsExcluded=true` is replayed into `tmedicalgetv2`.
2. A snapshot with `clientProvidedIdentifiersTrusted=true` is used as recovery authority.
3. A snapshot missing `serverDerivedAuthorityRequired=true` reaches ORCA transport.
4. A rejected snapshot leaks raw ORCA or patient/insurance details into tracked files.

## Implementation
- Billing snapshot generation now records `clientProvidedIdentifiersTrusted=false` and `serverDerivedAuthorityRequired=true` alongside `rawSensitiveFieldsExcluded=true`.
- Temporary medical reconcile payload generation now requires the sanitized server-derived snapshot metadata before reading visit date, department, or patient context.
- Focused tests cover client-trusted snapshot rejection.
