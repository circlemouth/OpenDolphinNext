# Iteration 20260510T105026Z

## Scope

- Checklist item: ORCA disease fetch results are stored in `orca_disease_cache` with source metadata and cache freshness information.
- Code surface: `server-modernized` ORCA disease mirror endpoint and focused persistence tests.

## Changes

- Added `OrcaDiseaseCacheStore` to persist successful `diseasegetv2` mirror projections as ORCA-derived cache rows.
- Wired `GET /api/local/diagnoses/{patientId}` to save connected ORCA mirror results with server-derived facility, patient, base month, department, insurance combination, request/trace IDs, fetch time, cache expiry, raw response hash, and normalized JSON payload.
- Kept raw ORCA response bodies out of cache payload fields; only a SHA-256 hash is persisted for raw response correlation.
- Treat cache write failure as part of mirror failure handling so the API does not present an uncached ORCA result as a clean success.

## Security Notes

- Client-provided facility, URL, owner, digest, storage key, and raw ORCA query values remain untrusted and are not accepted for cache authority.
- ORCA credentials, URLs, raw XML bodies, patient demographics, and insurance details are not written to tracked docs or evidence.
- Cache rows are explicitly marked `source_system=ORCA` and `source_api=diseasegetv2`; they are display/cache evidence, not a local disease master.

## Verification

- `mvn -f pom.server-modernized.xml -pl server-modernized -am -Dsurefire.failIfNoSpecifiedTests=false -Dtest=LocalDiagnosisResourceTest,OrcaDiseaseCacheStoreTest test` passed.

## Remaining Risk

- `GET /api/local/diagnoses/{patientId}` still accepts `from`/`to` rather than a first-class `baseMonth` parameter. The cache derives `base_month` from the server-side base date until the API contract is tightened.
- The stale state is persisted as `cache_expires_at`; a future UI/API slice should expose stale status explicitly where needed.
