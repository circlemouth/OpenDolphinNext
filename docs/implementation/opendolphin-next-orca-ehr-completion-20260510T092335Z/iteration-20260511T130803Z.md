## Threat Model

- Assets: candidate discovery summary, exact preflight handoff eligibility, `mutationPolicy`, sanitized patient / appointment / insurance readiness evidence.
- Trust boundaries: QA browser request observations and ORCA / local API responses are evidence inputs, not authority for Phase 3; Phase 3 still requires exact selected-candidate preflight and manual approved mutation flow.
- Attack surface: hidden mutation request during read-only discovery, mutation route pattern drift, blocked request evidence leaking query/body/patient/insurance/credential data.

## Misuse Cases

1. A UI path triggers `acceptance-operation`, `medical-mod-v2`, `disease-mod-v3`, local billing send, or temporary medical reconcile during candidate discovery and the older narrow regex misses it.
2. A blocked mutation URL includes patient ID, query token, insurance hint, or request body labels and the discovery artifact records it as reviewer evidence.
3. A discovery run with a blocked mutation still yields a selected candidate and is mistaken for Phase 3 handoff authorization.
