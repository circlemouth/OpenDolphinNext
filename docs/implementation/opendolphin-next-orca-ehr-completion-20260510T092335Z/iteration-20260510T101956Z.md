## Changes

- Removed `POST /api/local/diagnoses` from `LocalDiagnosisResource`.
- Removed local diagnosis mutation helpers and direct local-create/update/delete tests.
- Removed `mutateDiseases` and local diagnosis mutation payload tests from the web client API module.
- Updated `PublicRouteInventoryContractTest` so the local route inventory contains only `GET /api/local/diagnoses/{*}`.
- Updated route and ORCA connection contracts to state that `POST /api/local/diagnoses` is not public and disease mutation must use `/api/orca/official/chart-support/disease-mod-v3`.
- Updated `web-client/notes/disease-insurance-orca-contract.md` to keep Web client mutation on official disease-mod-v3.
- Marked the checklist item for local diagnosis create/update/delete route removal as complete.

## Threats And Mitigations

- Threat: local diagnosis rows can be created or updated and later displayed as if they were ORCA registered diseases.
  Mitigation: removed the public local POST route and client API helper; only the ORCA mirror read model remains.
- Threat: client payload can smuggle facility, patient, or disease authority into a local mutation.
  Mitigation: no local mutation payload is accepted; official disease mutation remains server-side ORCA bridge with server validation.
- Threat: unavailable ORCA mirror could fall back to local-only disease as the main disease truth.
  Mitigation: preserved existing GET tests that assert `diseases=[]` and local-only entries remain in `pendingLocalDiseases` when ORCA is unavailable.
