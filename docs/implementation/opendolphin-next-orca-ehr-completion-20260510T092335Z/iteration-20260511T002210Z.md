## Assets / Trust Boundary / Attack Surface

- Assets: prescription source-of-truth status, `orca_medical_candidate` prepare route, saved candidate rows.
- Trust boundary: client only supplies `chartRevisionId`; server resolves facility and current prescription order/revision from DB.
- Attack surface: `/api/local/orca/medical-candidates/from-chart/{chartRevisionId}`.

## Misuse Cases

- Client tries to prepare a candidate from a `DRAFT` prescription that has not been finalized.
- Client tries to prepare a candidate from a `STOPPED` or `CANCELLED` prescription and reintroduce stopped medication into send workflow.
- Client relies on stale UI state while server current prescription status has moved to cancelled/stopped.
- Candidate row is saved before status eligibility is checked.

## Implementation

- Added a fail-closed source-status guard in `LocalOrcaMedicalCandidateResource`.
- Candidate preparation now accepts only `FINAL`, `CHANGED`, and `REISSUED` prescription statuses.
- `DRAFT`, `STOPPED`, and `CANCELLED` sources return 409 `prescription_source_not_sendable` before candidate persistence.
- Documented the source-status boundary in `docs/contracts/prescription-authority.md`.
