## Pre-Implementation Boundary

- Assets: official patientmodv2 create/update routes, post-mutation patientgetv2, `orca_patient_cache`, local `d_patient` sync projection, ORCA patient mutation audit metadata.
- Trust boundary: browser payload and `auditMeta` are untrusted; facility comes from authenticated request context; ORCA patient source of truth is confirmed only by server-side patientgetv2 after mutation.
- Attack surface: facility/role spoofing, changedKeys abuse, ORCA mutation failure being shown as local update success, canonical re-fetch failure being hidden, raw ORCA body or patient detail leaking through response/audit.
- Misuse cases:
  1. Client sends forged facility/role/changedKeys to update another facility's patient.
  2. ORCA patientmodv2 succeeds but patientgetv2 returns not-found/warning and UI still shows sync complete.
  3. ORCA transport fails and server still imports local patient projection.
  4. Existing local patient row is treated as ORCA authority and skips canonical confirmation.
  5. Raw ORCA XML/JSON or patient address/phone detail is copied into tracked evidence or audit details.

## Implementation

- Added safe patient mutation response state: `orcaMutationPrepared`, `orcaMutationSent`, `canonicalRefetched`, `localSynced`, `canonicalSourceApi`, `canonicalCacheStatus`, `canonicalBusinessStatus`.
- Injected `OrcaPatientCacheStore` into patientmodv2 coordinator and enforced server-side patientgetv2 canonical re-fetch after accepted create/update and before local sync success.
- Made canonical re-fetch fail closed unless it returns `ORCA_PATIENT_FOUND` and cache status `CURRENT`; local sync is not called when re-fetch fails.
- Changed idempotent existing-patient create to avoid patientmodv2 send but still require patientgetv2 canonical re-fetch and local sync confirmation.
- Kept response/audit metadata allowlisted and raw-response-free; cache stores only hash/normalized summary via `orca_patient_cache`.
- Updated ORCA route and connection contracts plus checklist/worker board.
