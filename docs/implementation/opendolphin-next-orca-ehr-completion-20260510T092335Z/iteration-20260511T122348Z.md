## Assets / Trust Boundary / Attack Surface

- Assets: `encounter_orca_acceptance_link`, Charts local medical summary response, patient/acceptance/insurance warning and freshness metadata.
- Trust boundary: `orcaContext` is derived from authenticated facility context, `encounter_projection`, and server-side ORCA cache/link rows. Browser-provided patient, acceptance, insurance, facility, URL, storage key, or digest values are not authority.
- Attack surface: cross-facility encounterKey reads, raw patient/insurance detail leakage through warning payload, stale cache displayed as clear/current, client-side identifier smuggling into warning state.

## Misuse Cases

1. A user requests another facility's encounterKey to read warning metadata. Mitigation: local summary first resolves `encounter_projection` under the actor facility, and `orcaContext` is attached only when the link facility matches that projection.
2. Insurance diff display leaks insurance details or patient identifiers. Mitigation: response exposes only warning status, freshness timestamps, ORCA受付 context, and field-level changed-field names; raw insurance detail is not included.
3. Client sends patient/insurance/acceptance values and expects the server to synthesize warnings. Mitigation: local summary ignores client values and reads only saved `encounter_orca_acceptance_link` rows.
