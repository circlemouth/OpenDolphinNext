## Assets And Trust Boundary

- Asset: SOAP draft/save UI state and chart authoring workflow.
- Trust boundary: browser state is UX only. It must not replace server-side chart authority, finalization, authorization, or audit enforcement.
- Attack surface: disabled controls that hide the reason for refusal, read-only bypass attempts, and error/audit copy that could expose sensitive details.

## Misuse Cases

1. A finalized/read-only chart shows a disabled save button without a nearby reason, so the operator cannot distinguish lock state from a UI failure.
2. A history view blocks save without accessible explanatory text, increasing the chance of unsafe repeated navigation or copy attempts.
3. A save-in-progress state allows repeated activation or ambiguous feedback, risking duplicate user action expectations.

## Implementation

- Added `soap-note-save-block-reason` as the nearby reason element for `SoapNotePanel` save blocking.
- Kept native `disabled` for read-only, history view, and saving states because the operation cannot safely accept activation in those states.
- Linked the save button to the reason with `aria-describedby` and reused the same safe reason text for the title.
- Added focused Vitest coverage for the read-only save block reason and accessible association.
