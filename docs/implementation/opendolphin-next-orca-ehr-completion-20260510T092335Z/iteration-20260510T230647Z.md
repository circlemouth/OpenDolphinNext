## Assets / trust boundary / attack surface
- Assets: `chart_document`, `chart_revision`, `chart_revision_event`, content hashes, event reasons, before/after summary JSON.
- Trust boundary: HTTP request/session identity and DB-stored free text / JSON summaries are untrusted at export time; facility authority comes from the authenticated server context.
- Attack surface: facility-crossing export, raw ORCA/XML/credential leakage through reason/title/summary, malicious summary JSON adding patient/secret fields.

## Misuse cases
- A user from another facility guesses `chartId` and tries to export the revision chain.
- An event reason or title contains `Authorization`, `Cookie`, raw XML, or SOAP payload copied from an integration trace.
- A malformed or overbroad summary JSON includes patient name, raw ORCA body, CSRF token, or nested secret data.

## Implementation
- Added `GET /api/charts/{chartId}/revisions/export`.
- Added `ChartRevisionExportService` and DTOs for revision/event export.
- Export checks `chart_document.facility_id` against server-side facility context, returns revisions and events in deterministic order, and redacts unsafe text.
- Event summary projection now uses an explicit scalar allowlist rather than echoing arbitrary JSON.
