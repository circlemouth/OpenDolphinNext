# Iteration 20260511T145148Z - Worker F Audit Event Coverage Matrix Guard

## Scope

- Worker F R2-F08: audit event coverage matrix and release-gate drift prevention.
- Checklist coverage: 12/15/18/19 audit event coverage, append-only guard, sensitive evidence boundary.
- No A-D business implementation, E UI redesign, `client/`, or legacy `server/` changes.

## Threat Model

- Assets: authoritative audit event contract, hash-chain integrity, release evidence, audit coverage checklist, and reviewer-facing blocker records.
- Trust boundary: audit events may persist only sanitized identifiers, hashes, fixed status/reason codes, and request/trace identifiers; tracked docs may describe coverage but must not include raw PHI, credentials, raw ORCA body, browser artifacts, or raw network captures.
- Attack surface: audit contract drift, guard fixture gaps, reviewer packet summaries, release gate notes, and future worker changes that add business flows without audit event mapping.

## Misuse Cases

1. A new ORCA, chart, prescription, export, or admin flow ships without an authoritative audit event because append-only/hash-chain checks still pass.
2. A UI-only log or reviewer note is treated as audit coverage for PHI/export/admin/ORCA operations.
3. A failure state such as `UNKNOWN`, `AUTH_FAILED`, `CERTIFICATE_FAILED`, or `NEEDS_REVIEW` is omitted from audit coverage and later cannot be reconstructed.
4. Audit details include raw ORCA bodies, credentials, patient names, insurance details, raw invoice/data identifiers, HAR, trace, video, screenshot, or raw network evidence.

## Implementation

- Added `Required Event Coverage` to `docs/contracts/audit-log.md`.

- Extended `server-modernized/tools/ci/check-audit-append-only.sh` so the audit guard fails if the coverage matrix or required labels disappear.
- Added a negative `RepoGuardScriptsTest` fixture for missing coverage matrix.
