## Threat model
- Misuse case 1: UI 表示語を `Disease_Receipt_Print` や `Main_Disease_Class` の ORCA code として送信し、病名属性を誤登録する。
  - Mitigation: Web client 送信前 allowlist と server-side allowlist の二重検証で official transport 前に拒否する。
- Misuse case 2: レセプト表示期間に `100` など範囲外値を混入し、請求表示の意味を壊す。
  - Mitigation: client は blank / `None` / 2桁コードだけを許容し、server も同じ制約で再検証する。
- Misuse case 3: client-side 検証を authority と誤認し、facility / insurance / physician を client 値で決める。
  - Mitigation: contract に server-side authority を明記し、今回の client preflight は UX と早期検知に限定した。
