## Trust Boundary
- ORCA remains the patient authority; local search is only a picker/read model.
- Browser request keyword is not trusted as authority beyond selecting an exact cached ORCA patient row within the authenticated facility.
- ORCA cache fallback is display-only and does not authorize Phase 3 mutation by itself.

## Attack Surface
- Treating stale, NOT_FOUND, or NEEDS_REVIEW cache as selectable.
- Returning raw ORCA body, address, phone, insurance detail, credential, Cookie, Authorization, or CSRF through local search fallback.
- Using local search fallback as local patient CRUD or ORCA mutation approval.

## Misuse Cases
1. A caller searches an arbitrary patient ID and receives a stale or NOT_FOUND cache row as selectable.
2. A caller tries non-ID search or partial ID search to enumerate ORCA cache rows.
3. A QA run records local search response details into tracked evidence.
4. A downstream mutation script treats candidate discovery/local selectable alone as Phase 3 approval.

## Implementation
- Added an injected `OrcaPatientCacheStore` fallback in `LocalPatientSearchResource`.
- The fallback runs only when local `PatientModel` search returns 0 rows and the resolved search type is `PATIENT_ID`.
- It returns one minimal patient picker record only when the cache row is same-facility, exact patient ID, `cacheStatus=CURRENT`, `businessStatus=ORCA_PATIENT_FOUND`, and not expired.
- The fallback record intentionally omits address and phone, and does not return raw ORCA body or insurance details.
