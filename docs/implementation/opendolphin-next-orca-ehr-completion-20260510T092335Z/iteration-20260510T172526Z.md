## Threat Model

- Client sends a stale or edited prescription payload after the encounter has already moved to billing wait, causing local order display to diverge from the finalized billing workflow.
- Client tampers with `patientId` or `encounterId` to overwrite another encounter's prescription payload through the local prescription endpoint.
- DO import is used as an alternate mutation path after accounting handoff, bypassing the normal prescription save restrictions.

## Changes

- `LocalPrescriptionOrderResource` now checks the server-derived `encounter_projection` before persisting `/api/local/prescription-orders` and `/api/local/prescription-orders/do-import`.
- If the projection belongs to a different facility or patient, the route returns sanitized `encounter_not_found` without treating client identifiers as authority.
- If the projection is `accounting-wait`, `billing-waiting`, `closed`, `cancelled`, `chart-finalized`, `orca-sent`, or `orca_medical_registered`, the route rejects the mutation with `prescription_order_finalized_update_denied` before payload JSON is persisted.
- `LocalPrescriptionOrderResourceTest` covers save, DO import, and patient mismatch rejection.
- `docs/contracts/orca-route-taxonomy.md` records the local prescription mutation boundary and server-side encounter projection guard.
