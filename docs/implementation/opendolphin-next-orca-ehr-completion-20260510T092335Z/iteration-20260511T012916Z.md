## Trust Boundary
- Client payload is not authority for patient, facility, acceptance, department, physician, insurance, voucher, sequential, `Medical_Uid`, class code, URL, or raw XML.
- Billing send derives visit identifiers from server-side `encounter_projection` and its server-derived flags.
- Even inside the server projection, independently produced authority fields must agree before ORCA transport is reached.

## Attack Surface
- Stale projection flags carrying a voucher from a different ORCA acceptance.
- Accidental or malicious DB projection mismatch between `orca_acceptance_id` and `officialVisitIdentifiers.voucherNumber`.
- Client attempts to bypass authority alias rejection by relying on an already mismatched projection.
- Error and audit evidence leaking raw ORCA body, credentials, or patient/insurance details.

## Misuse Cases
1. A billing send for one encounter uses a voucher belonging to another ORCA acceptance.
2. A stale `officialVisitIdentifiers` block survives after an acceptance refresh and sends the wrong voucher.
3. A request avoids client-side authority aliases but reaches ORCA through inconsistent server-derived projection fields.
4. A failure path exposes raw ORCA payload or patient/insurance details in tracked evidence.

## Implementation
- `LocalEncounterBillingWorkflowResource` now rejects normal billing send when `officialVisitIdentifiers.voucherNumber` does not match `encounter_projection.orca_acceptance_id`.
- The guard runs before patient lookup, karte lookup, snapshot building, or ORCA transport.
- The focused test covers the mismatch path without configuring patient/karte/transport collaborators, proving the request stops at the boundary.
