## Scope

- Queue: A-04 insurance cache and encounter insurance snapshot boundary.
- Checklist: 3.2, 4, 6.
- Assets: ORCA `insuranceinf1v2` insurance combinations, `orca_insurance_cache`, `encounter_insurance_snapshot`.
- Trust boundary: facility, ORCA connection target, cache status, row hash, snapshot reason, and immutable snapshot behavior are server-side authority. Client-provided facility, role, URL, storage key, digest, and self-asserted insurance context are not authority.
- Attack surface: cross-facility insurance cache writes, raw ORCA body or insurance detail leakage, past encounter snapshot overwrite after ORCA insurance change, resend using stale snapshot without diff detection.

## Misuse Cases

- A caller tries to write another facility's insurance cache by sending facility-like data. Mitigation: the official wrapper uses authenticated request context for facility and ignores client facility/URL/storage/digest.
- ORCA returns sensitive insurance numbers or insured person names and the cache persists them. Mitigation: cache payload stores only allowlisted summary fields and public insurance count; raw response and detailed insurance identifiers are not stored.
- A later ORCA insurance change overwrites the encounter's original insurance snapshot. Mitigation: snapshot insert uses existing encounter/slot as immutable and returns changed field names instead of updating the original row.
- A resend preparation compares current ORCA cache with the encounter snapshot and misses a changed combination/department. Mitigation: snapshot re-create attempts return `diffDetected=true` with changed fields.
