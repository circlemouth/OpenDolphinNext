## Implementation
- Extended `OrcaReportDocumentResourceTest` to inject `OrcaBillingCacheStore`, capture `ReportSnapshotCommand`, and verify facility, ORCA patient, report type, invoice, request body, response body, and parsed response are passed to the server-side snapshot boundary.
- Added report resource fail-closed coverage: a valid ORCA report response is converted to HTTP 503 if `orca_report_snapshot` persistence fails.
- Extended `OrcaChartSupportResourceTest` to inject `OrcaBillingCacheStore`, capture `IncomeInfoCommand`, and verify facility, ORCA patient, base date, request body, response body, and parsed response are passed to the server-side billing cache boundary.
- Added income-info fail-closed coverage: a valid ORCA income response is converted to HTTP 503 if `orca_billing_cache` persistence fails.
- Updated checklist, worker board, and ORCA connection contract to state that public income/report responses require persisted sanitized cache/snapshot evidence.

## Threats / Mitigations
- Misuse case 1: A valid ORCA response is shown as business success while the local cache/snapshot write failed. Mitigation: resource tests now require HTTP 503 on billing cache or report snapshot persistence failure.
- Misuse case 2: Client-provided facility or storage authority bypasses server-side command construction. Mitigation: tests verify command facility is derived from the authenticated remote user and snapshot/cache commands are created inside the resource path.
- Misuse case 3: Raw evidence is relied on outside the audited cache/snapshot boundary. Mitigation: tests assert public resources hand sanitized command boundaries to the cache store before returning success; docs reiterate no raw ORCA body or client storage authority is evidence.
