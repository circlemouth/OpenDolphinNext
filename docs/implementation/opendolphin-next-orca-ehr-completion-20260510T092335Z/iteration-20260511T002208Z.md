## Threat Model

- Asset: active patient order editing context and the user-visible reason for blocked order mutation.
- Trust boundary: browser UI is not an authorization boundary; server-side order authority remains authoritative.
- Attack surface: patient context absence, read-only chart state, missing master data, fallback data, repeated clicks, and stale UI state.

## Misuse Cases

- A user attempts to add an order while required master data is missing and the UI silently blocks without explaining the reason.
- A user attempts to force quick-add from a read-only or fallback-data chart and opens an editor despite blocked prerequisites.
- A stale or missing patient context presents an active-looking order add control that can proceed into mutation UI.

## Implementation

- `OrderDockPanel` quick-add and group-add controls now keep push-time handling for patient/read-only/master/fallback blockers by using `aria-disabled=true`, nearby `order-dock-edit-block-reason`, and a click-time `オーダー追加を停止: ...` notice.
- The shared push-time guard exits before editor open, so blocked prerequisites do not reach order editor or mutation flow.
- Native `disabled` remains reserved for controls that cannot accept interaction safely, such as pending/loading or input-level states.
