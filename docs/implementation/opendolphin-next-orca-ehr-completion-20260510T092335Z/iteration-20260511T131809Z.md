## Pre-implementation model

- Assets: runtime-ready smoke artifact bundle, WebORCA candidate discovery summary, exact selected-candidate preflight boundary, and no-raw-artifact evidence policy.
- Trust boundary: browser/runtime evidence is diagnostic only until runtime-ready and exact preflight both pass; ORCA Trial data and credentials must not be copied into tracked docs or logs.
- Attack surface: raw browser/network artifacts after failure, unbounded candidate discovery hangs, timeout summaries being mistaken for mutation authorization, and local smoke rows being treated as official ORCA rows.

## Misuse cases

1. Candidate discovery stalls and the operator kills it, leaving raw network/browser artifacts that are later staged.
2. A runtime-ready no-row failure exits before writing a machine-readable blocker, so the next worker guesses based on terminal text.
3. A timeout summary or candidate discovery proposal is used as Phase 3 permission without exact selected-candidate readonly preflight.
4. A local smoke seed or UI-selectable patient is treated as official ORCA visit evidence.

## Implementation

- `runtime-ready-smoke.mjs` now writes sanitized `runtime-ready-before-row-wait.json` and `runtime-ready-result.json` when no official row exists for the current query date, then exits non-zero.
- `qa-weborca-candidate-discovery.mjs` now has `QA_CANDIDATE_DISCOVERY_TIMEOUT_MS` with a default of `180000`ms. Timeout writes sanitized `summary.json`, `summary.md`, exact preflight placeholder, and empty candidate rows, then exits `124`.
- Timeout evidence is explicitly `acceptedForPhase3Attempt=false`, `liveMutationExecuted=false`, and `rawSensitiveFieldsExcluded=true`.
- Release validation docs and the workstream checklist now distinguish these blocker summaries from runtime-ready pass, exact preflight pass, mutation, fullflow, or billing/report closeout evidence.
