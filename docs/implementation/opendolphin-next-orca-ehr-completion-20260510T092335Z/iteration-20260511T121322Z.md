## Threat Model

- Assets: ORCA cache responses, billing/report snapshot command payloads, chart export summaries, report binary upload bytes, audit/evidence hashes.
- Trust boundaries: REST resources and service callers can retain mutable DTO/list/map/byte-array references after handoff; cache, audit, hash, and restore code must use stable server-side snapshots.
- Attack surface: Java record constructors/accessors, DTO getters, command builders, chart export collection fields, report upload byte arrays.

## Misuse Cases

1. A caller mutates an ORCA response DTO after command creation so the persisted summary diverges from the audited response.
2. A returned chart export map/list is modified after authorization/export assembly to alter reviewer evidence or audit interpretation.
3. Report upload bytes are changed after digest/storage-key derivation to break binary report integrity.
4. Broad parse exception handling masks unexpected bugs and weakens cache restore triage.

- Removed SpotBugs duplicate-branch, redundant-null, and broad-catch findings without changing fail-closed behavior.
