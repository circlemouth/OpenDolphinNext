## Trust Boundaries

- ORCA `tmedicalgetv2` response body is external input.
- Raw ORCA body, parser exception details, credentials, patient detail, and insurance detail must not appear in response, audit, docs, or tracked evidence.
- Client-provided patient, facility, voucher, sequential, insurance, URL, and `Medical_Uid` remain non-authoritative.

## Attack Surface

- Malformed XML/JSON returned by ORCA or an intermediary.
- Response without `Api_Result` but with row-shaped data.
- Parser/runtime exception text that could reveal implementation details if copied to API response or docs.

## Misuse Cases

1. A malformed response attempts to trigger a server exception and expose parser details.
2. A response missing `Api_Result` includes matching row data and attempts to become a found temporary medical candidate.
3. A malformed response includes sensitive-looking fragments and attempts to leak raw body snippets into response or tracked evidence.

## Implementation

- Normalized missing or unparseable `Api_Result` to `unknown`.
- Added a fixed sanitized message `temporary_medical_reconcile_unparseable` when `Api_Result_Message` is absent on a non-success response.
- Kept the existing fail-closed row matching gate, so unparseable/missing-result responses cannot set matching rows, `Medical_Uid` presence, mode, or resend block.
- Added a focused test for malformed body behavior.
- Updated ORCA connection and route taxonomy contracts, worker board, and this iteration note.
