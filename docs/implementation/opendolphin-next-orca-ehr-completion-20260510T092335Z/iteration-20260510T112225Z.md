# Iteration 20260510T112225Z

## Scope

- Checklist item: `diseasev3` 送信の server-generated idempotency と `orca_disease_operation` 保存。
- Assets: `/api/orca/official/chart-support/disease-mod-v3`, `orca_disease_operation`, Charts disease mutation contract.
- Trust boundary: client does not provide idempotency key, facility, URL, raw XML, or authority fields. Server derives context, generates request XML, hashes it, and persists only sanitized summaries.

## Changes

- Added `OrcaDiseaseOperationStore` for `orca_disease_operation`.
- `diseasev3` now generates an idempotency key from server-generated request XML and rejects duplicate facility/key before ORCA transport.
- Completed disease operations store request/response hashes, fixed `operationStatus`, `needsUserReview`, warning/unmatch summaries, and non-sensitive request/response summaries.
- Updated focused tests for duplicate rejection and Postgres/Flyway-backed operation persistence.

## Misuse Cases

- Double click or replay submits the same diseasev3 request twice.
- Client attempts to choose idempotency, facility, URL, or raw XML authority.
- Operation evidence stores raw ORCA XML, credentials, or detailed patient/insurance data.
