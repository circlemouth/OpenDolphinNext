## Assets / Trust Boundary / Attack Surface

- Assets: ORCA response classification, operation status, warnings/unmatched summaries, request/response hashes, audit-safe response metadata.
- Trust boundary: ORCA transport response is external input; browser/client payload is not authority for facility, patient, role, URL, voucher, sequential, insurance combination, digest, or storage key.
- Attack surface: malformed ORCA response, misleading zero-like `Api_Result` without completion evidence, warning/unmatched response that could be collapsed into success, transport/auth/certificate failure that could be hidden as generic failure.

## Misuse Cases

1. ORCA returns zero-like `Api_Result` but lacks completion evidence; server must classify it as `UNKNOWN` and require review.
2. ORCA returns warnings or unmatched disease information with normal result code; server must set `ORCA_WARNING` / `ORCA_UNMATCHED` and `needsUserReview=true`.
3. Transport failures must not be collapsed into business rejection; HTTP auth failure, certificate/TLS failure, and network failure are distinct statuses.
4. Raw ORCA body, credential material, connection URL, patient detail, and insurance detail must not be stored in iteration evidence or response summaries.
