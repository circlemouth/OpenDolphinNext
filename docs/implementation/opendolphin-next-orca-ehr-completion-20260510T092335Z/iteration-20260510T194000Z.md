## Threat model

- Misuse case 1: Vite dev proxy reintroduces `/api21`, `/api01rv2`, `/orca22`, or other raw WebORCA paths and lets the browser reach ORCA directly.
- Misuse case 2: ORCA Basic credentials, certificate paths, certificate passwords, or prod credential variable names are added to client env files.
- Misuse case 3: client-side ORCA TLS bypass or ORCA response header filtering config is restored, moving server-side transport policy into the browser build surface.

## Controls

- `verify:no-direct-orca-proxy-config` scans Vite config and tracked web-client env files for raw ORCA/WebORCA paths and ORCA credential/certificate variables.
- `verify:web-guard` runs this guard before tests, typecheck, and build through existing npm hooks.
- Release validation now states this guard's expected security boundary explicitly.
