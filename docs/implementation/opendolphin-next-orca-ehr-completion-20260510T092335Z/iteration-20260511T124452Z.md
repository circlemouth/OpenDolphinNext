## Scope

One-heartbeat slice for checklist 11 / Phase 4: move the Charts normal `診察終了して会計へ送信` flow onto the common critical-operation modal. This covers UI confirmation only. Encounter close, billing send, ORCA transmission, accounting status, authorization, persistence, and audit enforcement remain server-side / owning workflow responsibilities.

## Assets, Trust Boundary, Attack Surface

- Assets: selected patient identity, visit date, reception/appointment references, disease/order/SOAP/image summary counts, finish intent, after-finish result, and the distinction between finish request, ORCA transmission, and accounted state.
- Trust boundary: browser route state, selected entry, confirmation summary, and button state are untrusted UI state. Server-side encounter projection, ORCA transmission state, accounting status, authorization, persistence, and audit remain authoritative.
- Attack surface: wrong-patient finish/billing send, unsaved-input guard bypass, blocked finish precheck bypass, user confusion between finish request and accounted state, and tracked evidence leaking credentials/raw ORCA body/PHI/HAR/trace/video/screenshot.

## Misuse Cases

1. A user closes the wrong patient's chart because the finish action proceeds without repeating patient context. Mitigation: finish now opens `CriticalOperationConfirmDialog` with patient ID, visit date, reception ID, appointment ID, and target summary before `onAfterFinish`.
2. A user has unsaved SOAP/order/disease inputs and the new confirmation bypasses the existing save/discard/cancel guard. Mitigation: the existing `onBeforeAction('finish')` path runs before the critical-operation confirm opens.
3. A blocked finish due to missing ORCA context still opens a confirmation dialog and appears actionable. Mitigation: existing `finishPrecheckReasons` fail-closed before the modal and continue to show the visible guard reason.
4. A finish request is mistaken for completed accounting. Mitigation: the modal summary explicitly states `会計済み確定ではありません`, and docs keep accounting status enforcement outside UI confirmation.
