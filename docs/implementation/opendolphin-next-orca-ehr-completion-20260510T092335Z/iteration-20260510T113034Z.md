# Iteration 20260510T113034Z

## Scope

- Checklist item: `diseasev3` transport failure is recorded as `NETWORK_FAILED` / `needsUserReview=true` and is not treated as success.
- Code scope: `server-modernized` ORCA chart support disease mutation resource and focused tests.
- Contract scope: ORCA connection contract, web disease/insurance ORCA contract, active EHR checklist.

## Threat Model

- A network exception after request XML generation could disappear before `orca_disease_operation` is written, leaving no reviewable failed operation.
- A transport failure could be collapsed into a generic exception and later misread as no mutation attempt.
- A persistence failure while recording the transport failure could mask the original ORCA transport exception.

## Changes

- `disease-mod-v3` now catches ORCA transport runtime exceptions after idempotency-key generation.
- The server writes a sanitized operation summary with `operationStatus=NETWORK_FAILED`, `needsUserReview=true`, no raw response body, and no ORCA credential or raw XML evidence in tracked docs.
- If operation persistence itself fails while recording the transport failure, the persistence exception is attached as suppressed and the original transport exception remains the primary failure.
- Added focused regression coverage that captures the saved operation command for a transport exception and verifies facility, operation, patient reference, generated idempotency key, request XML generation, absent response body, status, review flag, classification, and safe error token.
