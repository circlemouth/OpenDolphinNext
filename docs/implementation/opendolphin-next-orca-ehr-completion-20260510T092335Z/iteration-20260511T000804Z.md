# Worker B iteration 20260511T000804Z

## Queue
- Worker B B-05b: chart revision PDF/reporting payload integration for checklist 14.

## Assets / trust boundary / attack surface
- Assets: reporting PDF payload, chart revision event provenance, report summary section.
- Trust boundary: reporting API callers can submit arbitrary `chartRevisionEvents`; the payload is not authority and must be sanitized before template rendering.
- Attack surface: raw ORCA / credential text in reason fields, arbitrary summary keys exposing PHI or tokens, nested JSON being rendered directly into PDF output.

## Misuse cases
- A caller places `Authorization: Basic ...` or Cookie text into `reasonText`.
- A caller sends `Patient_Name`, `rawOrcaBody`, or `csrfToken` in before/after summary.
- A caller sends nested objects/arrays in summary to bypass field-level review and leak unbounded content.

## Implementation
- Added `ReportingChartRevisionEventPayload` and `ReportingPayload.chartRevisionEvents`.
- `ReportingEngine` now appends chart revision events to existing report summary items so current PDF templates render revision provenance without template duplication.
- PDF projection uses the same summary key allowlist concept as JSON export and redacts Authorization / Cookie / raw XML / SOAP body text.
- Non-scalar summary values are dropped instead of rendered.
