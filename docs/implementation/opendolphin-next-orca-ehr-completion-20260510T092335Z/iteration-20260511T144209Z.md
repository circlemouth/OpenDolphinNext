## Scope

One-heartbeat slice for checklist 11 / E-04 disabled reason follow-on: add an accessible nearby reason for the `PrescriptionOrderEditorPanel` `処方確定` button when it must remain native disabled for preview, save-pending, or finalize-pending states. This is a UI/a11y improvement only. Prescription finalize authorization, status transition, persistence, and audit enforcement remain server-side prescription workflow responsibilities.

## Assets, Trust Boundary, Attack Surface

- Assets: prescription finalize intent, patient/encounter context, editor state, pending mutation state, and user understanding of why the action is blocked.
- Trust boundary: browser disabled state, aria attributes, pending flags, and visible reason text are untrusted UI hints. The server remains authoritative for permission, prescription identity, status transition, content hash, and audit.
- Attack surface: unclear disabled actions that push users toward unsafe workarounds, double execution during pending mutations, and UI reason text being mistaken for authorization enforcement.

## Misuse Cases

1. A user sees `処方確定` disabled in preview and does not know how to enable it. Mitigation: the button is described by a nearby reason stating that normal input mode is required.
2. A user double-clicks or retries while save/finalize is pending. Mitigation: pending states keep native disabled and expose a reason until the current operation finishes.
3. A reviewer treats the disabled reason as a permission check. Mitigation: docs explicitly keep prescription finalize authorization and state transition enforcement on the server-side prescription workflow.
