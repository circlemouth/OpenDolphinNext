## Pre-implementation model

- Assets: Trial runtime configuration, ORCA connection status, runtime-ready smoke evidence, candidate discovery summaries, exact selected-candidate preflight summaries, billing/report closeout evidence, and sensitive evidence guards.
- Trust boundary: operator-provided approval and local runtime secrets are only prerequisites; they do not prove ORCA business acceptance. Docker-generated local config and Flyway logs are local execution artifacts and must not become tracked evidence.
- Attack surface: credential leakage from generated config/logs, treating dry-run as live success, running mutation before runtime-ready and exact readonly preflight, connecting Flyway to the wrong local PostgreSQL listener, and carrying stale DB/container state across worktrees.

## Misuse cases

1. A public Trial credential is copied into tracked docs, logs, or review packets instead of being supplied only through ephemeral environment variables.
2. A successful live checklist dry-run is reported as live Trial ORCA evidence even though runtime-ready smoke, candidate discovery, and exact selected-candidate preflight did not run.
3. Host Flyway connects to the wrong PostgreSQL port or stale local instance, so later ORCA evidence would be tied to an unverified runtime database.
4. A billing/report or `medicalmodv2` live mutation is attempted after partial setup without same-RUN_ID runtime and selected-candidate evidence.
