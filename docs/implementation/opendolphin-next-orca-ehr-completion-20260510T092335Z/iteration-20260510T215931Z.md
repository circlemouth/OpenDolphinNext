## Selected Task

D-03 was selected because D-01 and D-02 were already complete. This iteration hardens the close-and-send `medicalmodv2` workflow so that a zero-like ORCA response is not enough for user-visible completion unless server-side `tmedicalgetv2` re-fetch/reconciliation also succeeds.

## Assets / Trust Boundary / Attack Surface

- Assets: `medicalmodv2` send result, `tmedicalgetv2` read-only reconciliation, ORCA transmission state, encounter state transition, sanitized response summary, audit summary.
- Trust boundary: browser payload and ORCA response body are untrusted. Server-side encounter projection, saved snapshot, authenticated facility, and adapter-normalized ORCA status are the authorities.
- Attack surface: forged client identifiers, replayed idempotency key, ORCA zero-like response without completion evidence, missing `Medical_Uid`, raw ORCA body or raw identifiers leaking into persisted response/audit.

## Misuse Cases

1. A client tries to force accounting completion by sending voucher/sequential/insurance/`Medical_Uid`; these fields remain rejected before transport.
2. ORCA returns `Api_Result=00` but no completion evidence; the workflow keeps `UNKNOWN` / `needsUserReview=true`.
3. ORCA returns `Medical_Uid`, but `tmedicalgetv2` does not find a matching temporary medical row; the encounter is not moved to accounting-wait.
4. ORCA returns a matching row in a locked mode; the workflow returns `CORRECTION_REQUIRED` and blocks resend pending administrator review.

## Implementation

- Updated `LocalEncounterBillingWorkflowResource` to perform post-send `tmedicalgetv2` read-only reconciliation before `ORCA_MEDICAL_REGISTERED`.
- `Medical_Uid` returned by `medicalmodv2` is now necessary but not sufficient for completion.
- Completion remains blocked as `ORCA_UNKNOWN` when post-send reconciliation fails, is incomplete, or finds no matching row.
- Locked ORCA temporary medical mode now yields `CORRECTION_REQUIRED` with `needsUserReview=true`.
- Stored `response_json` now includes a sanitized `postSendReconciliation` summary with counts/statuses only; raw `Medical_Uid`, voucher, sequential, insurance combination, raw XML, and credentials are excluded.
- Updated ORCA connection contract, outage recovery runbook, checklist, and worker board.
