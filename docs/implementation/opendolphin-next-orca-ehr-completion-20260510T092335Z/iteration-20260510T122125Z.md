## Scope

This iteration completed the Web UI separation slice for disease display. It does not add persistence or ORCA write authority. It makes SOAP / chart-text disease-like mentions visible as chart-text truth and prevents them from being mixed into ORCA registered diseases or silently promoted to `diseasev3`.

## Changes

- Added a `診療録本文中の病名記載` read-only section to `DiagnosisEditPanel`.
- Passed short in-memory disease-like snippets from the current SOAP draft in `ChartsPage`.
- Kept the chart-text mention section action-free; ORCA registration still requires the separate `ORCAへ病名登録` confirmation flow.
- Updated focused tests to assert chart-text mentions are not shown in the ORCA mirror table and do not trigger mutation.
- Updated disease ORCA and UI current contracts.
- Marked the disease UI separation checklist item complete.

## Threats And Mitigations

- Threat: chart text could be misread as ORCA registered disease.
  Mitigation: chart text mentions render in a separate labeled section with explicit boundary copy.
- Threat: chart text could be silently promoted to ORCA `diseasev3`.
  Mitigation: the section has no mutation action; existing explicit confirmation remains the only ORCA send path.
- Threat: browser-side extracted snippets could become authority.
  Mitigation: snippets are derived from volatile SOAP draft display only and are not persisted, sent, or used as ORCA payload.
