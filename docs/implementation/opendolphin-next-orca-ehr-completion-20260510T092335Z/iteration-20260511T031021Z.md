## Assets
- `d_billing_orca_snapshot.snapshot_json.visitDate`
- ORCA `tmedicalgetv2` response rows
- Temporary medical reconcile match count and resend block decision

## Trust Boundary
- Saved snapshot visit date is the server-side authority for the reconcile attempt.
- ORCA read-only response rows are external input and must match the saved snapshot before being treated as candidates.
- Client payload remains unused.

## Attack Surface
- Same patient and department row from a different perform date being counted as a temporary medical match.
- A different-date `Medical_Uid` influencing resend or admin-review decisions.
- Sanitized response summary incorrectly presenting a cross-date row as a recovery candidate.

## Misuse Cases
1. ORCA returns the same patient and department for a different perform date.
2. A different-date row contains `Medical_Uid` and is counted as present.
3. A different-date row with locked `Medical_Mode2` blocks resend for the wrong encounter date.
4. Evidence or logs expose raw ORCA body or patient/insurance details while diagnosing mismatch.

## Implementation
- Temporary medical row matching now compares `Perform_Date`, `Medical_Date`, or `Visit_Date` from ORCA rows to the saved snapshot `visitDate` when the response row includes one.
- Different-date rows are not counted as matches and do not mark `Medical_Uid` present.
- Focused test covers a same-patient, same-department, different-date ORCA row.
