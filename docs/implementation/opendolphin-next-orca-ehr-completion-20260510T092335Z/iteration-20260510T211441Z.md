## Assets / Trust Boundary / Attack Surface

- Assets: `prescription_order`, `prescription_order_revision`, `prescription_order_item`, `prescription_order_event`, prescription content hash, audit event metadata.
- Trust boundary: browser JSON is untrusted; facility and actor come from authenticated server context; patient existence is checked server-side; FINAL+ transitions are represented by server authority API and DB triggers.
- Attack surface: `/api/prescriptions`, `/api/prescriptions/{prescriptionId}/finalize`, `/api/prescriptions/{prescriptionId}/change|stop|cancel|reissue`, direct SQL/ORM mutation of finalized rows.

## Misuse Cases

- Client submits a forged `patientId` / `encounterId` in change or reissue payload to move an existing prescription to another patient.
- Client finalizes with a forged digest to make a different prescription body appear authoritative.
- Client directly updates or deletes finalized order/revision/item rows, or rewrites events to erase stop/cancel/change history.
- Client calls stop/cancel/change/reissue without a clinical reason.

## Implementation

- Added `PrescriptionAuthorityResource` under `/api/prescriptions` with create, finalize, change, stop, cancel, and reissue routes.
- Added API DTOs for prescription authority mutation request/response.
- Added `PrescriptionAuthorityRepository` that writes structured revisions/items/events and computes content hash from server-side canonical summaries.
- Kept direct FINAL+ row mutation denied by default, while allowing only the server authority transaction to append revision/event transitions via scoped PostgreSQL setting.
- Registered the resource in `OpenDolphinRestApplication`.
