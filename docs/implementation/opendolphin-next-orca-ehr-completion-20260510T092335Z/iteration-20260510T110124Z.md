# Iteration 20260510T110124Z

## Scope

- Checklist item: `GET /api/local/diagnoses/{patientId}?baseMonth=...` ORCA disease mirror read model.
- Code surface: `server-modernized` local diagnosis read model and focused regression tests.

## Changes

- Added explicit `baseMonth=yyyyMM` handling to the Charts ORCA disease mirror read model.
- The server validates `baseMonth` before patient/Karte/ORCA lookup and rejects malformed values with `400 invalid_base_month`.
- A valid base month is converted server-side to the ORCA `Base_Date` and to the `orca_disease_cache.base_month` value; client-provided facility, URL, owner, digest, raw XML, and ORCA query fields remain ignored.
- Updated route taxonomy and ORCA disease mirror contracts to describe the `baseMonth` authority boundary.

## Security Notes

- Misuse case: malformed `baseMonth` attempting parser confusion or unexpected ORCA query values. Mitigation: strict six-digit `yyyyMM` validation and fail-closed `400`.
- Misuse case: client attempts to steer facility or ORCA endpoint. Mitigation: facility remains resolved from authenticated request context; ORCA transport configuration and allowlist remain server-owned.
- Misuse case: client tries to create local disease truth by picking a cache context. Mitigation: the endpoint still returns ORCA projection only as `diseases`, keeps local-only diagnoses isolated as `pendingLocalDiseases`, and stores cache as `source_system=ORCA`.
