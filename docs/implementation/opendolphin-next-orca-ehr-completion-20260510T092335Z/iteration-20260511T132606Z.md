## Threat Model

- Assets: chart revision chain, `chart_revision_event`, authoritative `audit_event` hash chain, export-visible event provenance.
- Trust boundary: request payload reason/content/actor is untrusted; facility and persisted chart/revision/event metadata are server-side state.
- Attack surface: mutation success without authoritative audit evidence, raw reason text or raw ORCA/credential/PHI copied into audit payload, facility-mismatched chart revision event.

## Misuse Cases

1. An amend/addendum/cancel request records `chart_revision_event` but skips authoritative audit, leaving export provenance without hash-chain evidence.
   - Countermeasure: record `CHART_REVISION_EVENT_RECORDED` after event persistence and fail closed if the audit service cannot append.
2. A malicious reason contains `Authorization`, `Cookie`, raw XML, or patient/insurance details and attempts to persist them into audit payload.
   - Countermeasure: audit details include only chart/revision/event/hash/status metadata; focused audit sanitizer test verifies raw reason and cookie fields are dropped.
3. A facility-mismatched chart revision request tries to create an audited event for another facility.
   - Countermeasure: existing facility check remains before event persistence and audit recording.
