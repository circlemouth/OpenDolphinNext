## Threat Model

- Assets: chart revision export payload, CSV/PDF provenance inputs, export hash, prescription history, ORCA operation/transmission/reconciliation ledger metadata, snapshot manifest references.
- Trust boundaries: authenticated facility context versus chart facility, local chart revision records versus ORCA-derived ledger summaries, export serialization versus spreadsheet/PDF consumers.
- Attack surface: chart export endpoints, native ledger joins, summary JSON projection, CSV cell rendering, canonical export hash material.

Misuse cases:

1. A caller requests a chart outside its facility and tries to obtain ORCA operation metadata.
2. ORCA ledger summary JSON contains raw ORCA body, credential, PHI, or arbitrary nested fields and attempts to leak through JSON/CSV export.
3. ORCA status or transport status starts with a spreadsheet formula prefix and attempts CSV formula execution.
4. ORCA transmission status/hash changes but `exportHash` does not change, hiding history tampering or missing rows.

## Implementation

- Added `ChartRevisionExportOrcaEvent` and `orcaEvents` to the chart revision export response.
- Extended `ChartRevisionExportService` to load ORCA operations by server-side facility and exported chart revision ids, joining the latest transmission and latest reconciliation status.
- Export projection includes only status/type/source, request/response hashes, retry/review metadata, latest transmission attempt/status/hash, reconciliation status, and allowlisted scalar summaries.
- Excluded idempotency key, raw request/response body, raw ORCA body, credentials, request IDs, trace IDs, patient details, and arbitrary summary keys.
- Added ORCA event rows to CSV export with existing spreadsheet formula neutralization.
- Added ORCA event material to canonical `exportHash`.
- Updated document-integrity contract, checklist, and worker board.
