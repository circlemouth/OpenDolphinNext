## Assets And Trust Boundary

- Assets: billing/report live handoff summary, operator result input JSON, `qa/billing-report-live-result/result.sanitized.json`, reviewer packet evidence.
- Trust boundary: operator result input is untrusted local evidence. The template must show only allowlisted hash/status fields and must not encourage raw patient, invoice, ORCA body, report body, storage key/digest, credential, or browser artifact capture.
- Attack surface: operator copying raw ORCA response fields into result input, storage key/digest exposure, browser artifact references in example contracts, template output creating local artifacts that appear reviewable.

- Added `--print-operator-result-template` to `qa-orca-billing-report-live-result.mjs`; it prints a no-write JSON input template and exits before normal validation/output.
- Added Node tests proving the template is accepted by the result wrapper and contains no raw-sensitive key names in the input object.
- Updated release-validation, reviewer submission packet runbook, scripts tools reference, checklist, worker board, and this iteration doc.

## Misuse Cases And Mitigations

- Misuse case: operator uses raw `Data_Id`, invoice number, patient identifier, storage key, or storage digest as example fields. Mitigation: template contains only hash/status fields and the wrapper rejects raw-sensitive key names.
- Misuse case: operator records HAR, trace, video, screenshot, raw network, or raw ORCA/report body. Mitigation: template claim boundary and runbooks explicitly forbid adding those fields; wrapper and packet validators reject artifact references.
- Misuse case: template command writes evidence that is mistaken for a completed result. Mitigation: `--print-operator-result-template` only prints JSON and exits before artifact directory creation.
- Misuse case: result input is interpreted as paid status or local report authority. Mitigation: template and result summary keep claim boundary as ORCA-derived cache/snapshot evidence only.
