# Worker B iteration 20260511T002815Z

## Queue
- Worker B B-06: delegated chart entry/finalizer context for checklist 7.

## Assets / trust boundary / attack surface
- Assets: `chart_revision.entered_by_user_id`, `finalized_by_user_id`, `entry_mode`, `delegated_by_user_id`, finalize context JSON, FINALIZED event summary, JSON/CSV/PDF provenance projection.
- Trust boundary: finalize request JSON is client-controlled; stored draft revision metadata and authenticated server-side document lookup are the authority.
- Attack surface: client role/owner claims, forged delegated entry mode, direct finalized revision mutation, export/reporting summary projection.

## Misuse cases
- A client sends `entryMode=DIRECT` while a different user finalizes a draft entered by a delegate to hide delegated entry.
- A client sends `entryMode=DELEGATED` for a same-user finalize to manufacture a false delegation record.
- A client sends `delegatedByUserId` for another user to attribute final approval to someone other than the server-validated finalizer.

## Implementation
- Added `ChartRevisionEntryMode` and migration `V0320__chart_revision_delegated_entry_context.sql` with `DIRECT` / `DELEGATED` enum constraint and delegated context consistency check.
- `ChartRevisionFinalizeService` now requires stored `enteredByUserId`, derives `entryMode` from stored entered-by vs request finalizer, rejects mismatched client-provided mode, and requires delegated-by to match finalizer when delegated.
- Finalize context JSON and FINALIZED event summary now include `enteredByUserId`, `entryMode`, `delegatedByUserId`, and `finalizedByUserId` without patient name or raw ORCA body.
- Amend/addendum revision creation preserves source entry mode and delegated context while recording the new finalizing actor separately.
- Chart JSON/CSV export and reporting summary allowlists include entry/finalizer metadata while retaining scalar allowlist and redaction.
