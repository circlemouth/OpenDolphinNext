## Threat Model

- ORCA `Disease_Unmatch_Info` can indicate diseases present on ORCA that do not match the submitted mutation. Dropping it would hide a reconciliation risk from later review.
- ORCA `Organize_Information` can indicate deletion cleanup / renumbering context. Dropping it would make post-send audit and reconciliation incomplete.
- Raw ORCA XML or verbose ORCA messages could leak patient or infrastructure details if persisted directly.

## Changes

- Added sanitized `unmatchInformationOverflow` and `organizeInformation` fields to `ChartSupportDiseaseModV3Response`.
- The parser now accepts both the existing `Disease_Unmatch_Information_child` shape and the official `Disease_Unmatch_Info_child` shape.
- ORCA-only disease rows preserve only bounded review fields: code, name, supplement name, in/out, category, suspected flag, start date, end date, and outcome.
- Renumbering / deleted-disease organization response preserves only department code and disease start date.
- `orca_disease_operation.response_summary_json` now records unmatch overflow and whether organize information was present, without raw XML or credential material.
