## Pre-Implementation Boundary

- Assets: official `GET /api/orca/official/patientgetv2`, `orca_patient_cache`, ORCA patient read audit, ORCA route/connection contracts.
- Trust boundary: browser query is untrusted. Facility is resolved from authenticated request context. ORCA response is external input and is classified before cache metadata is persisted.
- Attack surface: facility crossing, patient identifier tampering, patient-not-found misclassification, stale cache treated as current ORCA truth, raw response or credential leakage in audit/evidence.
- Misuse cases:
  - A client tries to influence facility or owner context through headers/query.
  - `Api_Result=10` patient-not-found is presented as a normal patient because HTTP status is 200.
  - ORCA outage causes old local cache to be promoted as current patient truth.
  - Raw ORCA body, URL, credential, Cookie, Authorization, CSRF, or patient detail is copied into audit details or tracked evidence.

## Implementation

- Added `V0315__orca_patient_cache.sql` with ORCA source metadata, cache/business status, fetched/cache expiry timestamps, raw response hash, and normalized/summary JSON without raw response storage.
- Added `OrcaPatientCacheStore` to classify `patientgetv2` responses, store normalized ORCA patient cache rows, and map patient-not-found to `ORCA_PATIENT_NOT_FOUND`.
- Updated `OrcaPatientApiResource` to persist the patient cache on live ORCA reads and return source/cache/stale/business metadata via response headers while preserving the existing ORCA-compatible response body.
- Updated focused resource/schema/cache tests.
- Updated `docs/contracts/orca-route-taxonomy.md`, `docs/contracts/orca-connection.md`, and the workstream checklist.
