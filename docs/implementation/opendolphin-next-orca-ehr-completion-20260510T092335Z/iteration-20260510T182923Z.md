## Threat Model

- Misuse case 1: patientmodv2 の write accepted を、ORCA正本再取得済みの full success と誤認する。
- Misuse case 2: `canonical 再取得` / `完了扱い` の内部語が Patients 画面や API result message 経由で利用者に表示され、業務状態を誤解する。
- Misuse case 3: ORCA既存患者取込の partial / skipped-only result を、取込完了や登録済みとして扱う。

## Changes

- `patients/api` の patientmodv2 result message を、内部 `canonical` 用語ではなく ORCA正本の再取得による同期確認表現へ変更した。
- `orcaPatientImportApi` の canonical re-fetch failure / partial import message を、同期確認未完了または同期確認済みにできない状態として返すよう変更した。
- `PatientsPage` の success toast、selection notice、監査 summary copy を、取込/保存完了ではなく ORCA正本再取得による同期確認として表示するよう変更した。
- focused tests で Patients / outpatient import の visible and API message に `canonical 再取得` / `完了扱い` が残らないことを固定した。
