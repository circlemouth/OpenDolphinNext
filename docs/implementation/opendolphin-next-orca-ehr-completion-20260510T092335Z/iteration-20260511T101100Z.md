## Assets / Trust Boundary / Attack Surface

- Assets: chart revision chain, `snapshot_manifest_json`, JSON/CSV export payload, `exportHash`, reporting/PDF provenance path, document integrity contract.
- Trust boundary: browser/client request is not authority; export uses server-side facility session plus DB-persisted revision/event/manifest data. Manifest data is still treated as untrusted for output and is projected through an allowlist.
- Attack surface: raw ORCA body or Authorization/Cookie embedded in manifest, allowlist bypass through nested JSON or extra keys, prescription/ORCA reference tampering that does not change export hash, CSV formula injection.

## Misuse Cases

1. A manifest contains `patientName`, `rawOrcaBody`, or `Authorization`; export must not return those keys.
2. A manifest contains prescription candidate / ORCA operation references and content hashes; changing allowlisted values must change `exportHash`.
3. A manifest contains nested or non-scalar sensitive objects; export must ignore them because only allowlisted scalar/array values are projected.
