## Implemented Scope

- Added `POST /api/local/encounters/orca-transmissions/{transmissionId}/reconcile-temporary-medical`.
- The endpoint is read-only and only loads `ORCA_UNKNOWN`, `ORCA_FAILED`, or `CORRECTION_REQUIRED` review transmissions for the authenticated facility.
- The `tmedicalgetv2` request is generated from persisted server-side snapshot data: patient ID, perform date, and department code.
- The client cannot provide facility, patient, insurance combination, voucher, sequential number, `Medical_Uid`, URL, raw XML, or ORCA identifiers for reconciliation.
- The response returns only a sanitized summary: row counts, matching row count, `Medical_Uid` presence, medical mode values, fixed `needsUserReview=true`, and a review status.
- The audit event stores sanitized reconciliation metadata and does not store raw ORCA bodies, credentials, insurance detail, `Medical_Uid` value, or patient demographics.

## Threats And Mitigations

- Client-side identifier tampering: ignored by design because the endpoint accepts only the path `transmissionId` and re-loads facility-scoped server records.
- ORCA raw data leakage: response and audit store presence/count/status only; raw XML and `Medical_Uid` values are not returned or persisted by this flow.
- Unsafe automatic resend: reconciliation does not transition billing state and always returns `needsUserReview=true`.
