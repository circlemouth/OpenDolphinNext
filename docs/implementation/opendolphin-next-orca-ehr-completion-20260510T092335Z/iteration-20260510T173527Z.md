## Threat Model

- Vite dev proxy reads ORCA Basic credentials or client certificate material and turns the browser development process into an ORCA transport authority.
- Browser code or dev proxy exposes raw ORCA/WebORCA paths such as `/api21`, `/api01rv2`, or `/orca22`, bypassing server-side audit, route taxonomy, allowlist, and response normalization.
- A future change reintroduces ORCA transport mode/path-prefix settings into web-client env samples, causing credentials or transport decisions to drift from server-modernized.

## Changes

- Removed raw ORCA/WebORCA proxy entries from `web-client/vite.config.ts`.
- Removed Vite-side ORCA Basic header injection, client certificate agent loading, ORCA response header filtering knobs, and ORCA path prefix logic.
- Changed `web-client` `npm run dev` to start Vite directly instead of loading ORCA env files.
- Added `verify:no-direct-orca-proxy-config` and included it in `verify:web-guard`.
- Removed obsolete Vite ORCA mode/path-prefix and insecure proxy TLS sample settings.
- Updated web-client security/current docs and ORCA certification operations docs to state that ORCA credentials and raw transport stay server-side.
