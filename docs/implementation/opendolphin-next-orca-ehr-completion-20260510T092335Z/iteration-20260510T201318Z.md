## Threat Model

- Assets: `opendolphin.audit_event`, `opendolphin.audit_chain_head`, audit outbox, hash-chain verifier.
- Trust boundary: application audit writers and future repository/API code are untrusted until CI guard verifies they cannot mutate authoritative audit events.
- Attack surface: production SQL literals, repository public methods, missing verifier path, and readiness semantics that could imply audit availability without chain validation.

Misuse cases:

1. A production resource adds `DELETE FROM opendolphin.audit_event` for cleanup.
2. A repository exposes a public `update` or `delete` method for authoritative audit events.
3. `AuditChainVerifier.verifyAll()` is removed, leaving no supported chain validation path.
