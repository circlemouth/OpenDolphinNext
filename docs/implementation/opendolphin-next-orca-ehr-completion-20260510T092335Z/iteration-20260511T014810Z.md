## Assets / trust boundary / attack surface
- Assets: `exportHash`, sanitized summary projection, snapshot manifest projection, redacted reason/title/context strings.
- Trust boundary: database rows and API output are server-side, but exported JSON may later be compared across systems or archives.
- Attack surface: JSON key order differences, allowlist-excluded keys, raw secret values inside redacted strings, and accidental hash instability.

## Misuse cases
- A stored snapshot manifest includes excluded `patientName` or `rawOrcaBody` keys that should not affect export verification.
- Authorization or raw XML values differ before redaction and accidentally influence verification artifacts.
- Semantically identical snapshot JSON with different key order produces a different `exportHash`.

- Added a regression test proving `exportHash` remains stable across excluded keys, raw secret differences after redaction, and snapshot JSON key order changes.
