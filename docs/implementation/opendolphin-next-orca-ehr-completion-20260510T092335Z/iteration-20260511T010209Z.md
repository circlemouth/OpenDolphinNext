- Surface: `OrderDockPanel` prescription-history import controls.

## Threat Model

- Asset: active patient prescription-history import context and visible blocked-operation reason.
- Trust boundary: browser UI is not an authorization boundary; server-side prescription/order mutation authority remains authoritative.
- Attack surface: missing patient context, read-only chart state, missing master data, fallback data, stale history import, and copy-to-editor entry.

## Misuse Cases

- A user attempts to start a new prescription from history while master data is missing and receives only a silent disabled control.
- A user attempts to copy the latest prescription from a read-only or fallback-data chart and opens the prescription editor despite blocked prerequisites.
- A stale or missing patient context presents history import controls as available without explaining why import is blocked.

## Implementation

- `OrderDockPanel` prescription-history `新規（空）` and `直近処方をコピーして開始` controls now use `aria-disabled=true`, nearby `order-dock-edit-block-reason`, and push-time blocked notices for patient/read-only/master/fallback blockers.
- History import exits before editor open when blocked.
- Native `disabled` remains for the no-latest-prescription state, where there is no import target to invoke.
