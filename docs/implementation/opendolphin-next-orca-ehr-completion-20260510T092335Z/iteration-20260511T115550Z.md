## Assets / Trust Boundary / Attack Surface

- Assets: ORCA patient cache, ORCA insurance cache, `encounter_orca_acceptance_link`, patient/insurance freshness warning state, sanitized live-readiness evidence.
- Trust boundary: patient/insurance freshness and warning state are server-derived from authenticated facility context, ORCA cache writes, and existing encounter link rows. Browser-provided patient/insurance identifiers are not authority.
- Attack surface: client identifier injection into freshness state, stale cache treated as current, raw patient/insurance details leaking through diff/warning evidence, cache update side effects mutating encounter workflow state.

## Misuse Cases

1. Client supplies patient or insurance identifiers to mark an encounter fresh. Mitigation: link refresh is performed by server-side patient/insurance cache stores using DB rows and authenticated facility scope only; authority flags remain constrained.
2. Stale or unavailable ORCA cache is displayed as current. Mitigation: patient/insurance warning fields default to stale/unresolved and clear only when current ORCA cache confirms found/current data.
3. Insurance diff warning exposes insurer or patient details. Mitigation: the encounter link stores only cache status and field-level sanitized `insurance_changed_fields_json`; raw ORCA body and insurance detail are not persisted.
