## Assets, Trust Boundaries, Attack Surface

- Assets: ORCA Trial connectivity, selected-candidate preflight identity, acceptmodv2 mutation status, sanitized live evidence, billing/report closeout eligibility.
- Trust boundaries: browser UI and QA harness are not authority; exact preflight summary hash and input identity hash gate Phase 3 mutation; ORCA response is external input and is recorded only as a sanitized business classification.
- Attack surface: stale UI selectors causing false blocker or wrong candidate selection, accidental mutation without exact preflight, raw network/browser artifact retention, credential/header leakage, candidate-discovery proposal being mistaken for mutation approval.

## Misuse Cases

1. A stale Reception button locator reports `local_search_failed` even when a Trial-native candidate is selectable, causing live blocker evidence to be misleading.
2. Candidate discovery proposal is reused as mutation authorization without exact selected-candidate readonly preflight and input identity binding.
3. Fullflow or diagnostic harness keeps network JSON, screenshots, HAR, XML, or raw ORCA body while `QA_SANITIZED_EVIDENCE_ONLY=1` is expected.
4. Approved acceptmodv2 runs with a mismatched preflight summary hash or input identity hash.
