## Threats And Mitigations

- Threat: ORCA disease cache and local/pending disease rows collapse into one table and become a hidden local disease authority.
  Mitigation: introduced separate ORCA-named tables for cache, snapshot, operation, and audit instead of reusing `d_diagnosis`.
- Threat: ORCA warnings/unmatched results are reduced to success/failure and lost.
  Mitigation: cache, snapshot, operation, and audit tables all include structured warnings/unmatched summary JSON columns.
- Threat: raw ORCA XML, credentials, patient details, or insurance details leak into tracked schema/evidence.
  Mitigation: schema stores hashes and normalized/sanitized JSON summaries only; docs explicitly prohibit raw ORCA XML and secrets in these tables.
- Threat: duplicate diseasev3 submission after retry.
  Mitigation: `orca_disease_operation` has a unique `(facility_id, idempotency_key)` constraint and retry count.
