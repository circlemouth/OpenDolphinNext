## Threat Model

- Assets: web full CI release gate, billing/report live profile sanitized evidence summaries, ORCA send UI regression tests, reviewer packet evidence boundary.
- Trust boundary: sanitized evidence may include safe correlation fields such as `traceId`, but must not include browser trace archives, HAR, screenshots, raw ORCA identifiers, credentials, or PHI.
- Attack surface: broad deny regexes can either block safe gate evidence and hide true blockers, or be loosened so far that raw artifacts slip through.
- Misuse cases:
  - A safe `traceId` field is treated as a forbidden trace archive and blocks `npm run ci`, preventing release gate signal.
  - A test accepts raw `trace-*.zip`, HAR, video, screenshot, or raw `Medical_Uid` because it only checks a generic word list.
  - ORCA send completion tests match explanatory copy instead of the completion status, allowing future UI wording drift to mask raw invoice/data id leakage checks.
