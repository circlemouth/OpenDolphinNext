## Scope
- `close-and-send-to-billing` の `ORCA_UNKNOWN` 結果に `operationStatus=UNKNOWN` と `needsUserReview=true` を通す。
- `Medical_Uid` 欠落または transport ambiguity による unknown response を、保存用 sanitized summary にも同じ固定分類で残す。
- idempotency key で既存送信履歴を返す場合も `ORCA_UNKNOWN` は `confirmationRequired=true` / `needsUserReview=true` として返す。

## Threats And Controls
- Threat: `ORCA_UNKNOWN` が成功または単なる失敗として丸められ、無条件再送される。
  - Control: API response と stored summary に `UNKNOWN` / `needsUserReview=true` を固定保存し、再照合前の成功扱いを防ぐ。
- Threat: 通信例外や missing `Medical_Uid` の詳細が tracked evidence に残る。
  - Control: summary は status、Api_Result、fixed operation status、boolean flags だけを保存し、raw XML、接続先、資格情報、患者詳細、保険詳細は含めない。
- Threat: client が ORCA identifiers を authority として再送判断する。
  - Control: close-and-send request は引き続き `idempotencyKey` と precheck flag だけを受け付け、server-derived encounter context から送信する。
