# Worker E Iteration 20260511T020213Z

## Scope
- Queue: E-04 follow-on.
- Checklist: 11 disabled dependency reduction; 20 Phase 4 Medical Safety UI / DADS.
- Surface: `OrderBundleEditPanel` embedded footer submit controls used from OrderDock detail editing.

## Threat Model
- Asset: patient-scoped order mutation workflow and clinical order edit state.
- Trust boundary: browser UI state is advisory only; mutation authorization and validation remain server-side responsibilities.
- Attack surface: read-only, missing master, fallback data, and preview states that previously made save controls inert without push-time reason.

## Misuse Cases
- A user sees footer save controls disabled and cannot distinguish missing master from read-only or fallback data.
- A future regression lets a blocked embedded editor attempt mutation without displaying the blocked reason.
- Assistive technology exposes blocked save controls without a related reason.

## Implementation
- Kept native disabled for save-in-progress only.
- Changed embedded footer submit controls to expose `aria-disabled=true`, `data-disabled-reason=order_detail_submit_blocked`, and the nearby edit block reason while still accepting click.
- `submitAction` now reports `保存操作を停止: ...` and keeps the existing blocked audit path before mutation.
