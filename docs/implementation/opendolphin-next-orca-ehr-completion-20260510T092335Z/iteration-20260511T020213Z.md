## Assets And Trust Boundary

- Assets: `qa/billing-report-live-profile/summary.sanitized.json`, reviewer submission packet `closeout-packet/`, closeout evidence manifests, ORCA billing/report release evidence contract.
- Trust boundary: closeout evidence is input to packet generation, not authority to broaden evidence. The packet tool must copy only allowlisted sanitized files and must not infer live ORCA success from a dry-run readiness summary.
- Attack surface: malicious or stale closeout summary, raw artifact path references, live execution claim drift, raw patient / invoice / `Data_Id` / credential keys embedded in JSON.

## Implementation

- Added `qa/billing-report-live-profile/summary.sanitized.json` to reviewer packet required closeout inputs and required packet outputs.
- Added validation for billing/report dry-run summary provenance, command contract, `dryRun=true`, `liveTrialOrca.executed=false`, sanitized evidence flags, server-generated storage key/digest boundary, and forbidden raw evidence fields.
- Added key/path leak guards for raw patient identity, raw invoice / `Data_Id` / `Medical_Uid`, credential headers, request XML, HAR, and raw network references.
- Added focused Node tests for successful packet inclusion, live execution claim rejection, and raw diagnostic artifact rejection.
- Updated reviewer packet and release-validation runbooks, checklist, worker board, and this iteration doc.

## Misuse Cases And Mitigations

- Misuse case: a dry-run billing/report summary is presented as live ORCA execution or paid/receipt authority. Mitigation: packet validation requires `liveTrialOrca.executed=false`; docs state the summary is gate evidence only.
- Misuse case: the packet generator copies broad billing/report evidence with raw ORCA bodies or browser artifacts. Mitigation: only one sanitized JSON file is allowlisted and copied.
- Misuse case: closeout JSON embeds raw patient ID, invoice number, `Data_Id`, `Medical_Uid`, credential headers, request XML, HAR, or raw network references. Mitigation: key-level and text-level validation fails packet creation/validation.
- Misuse case: client-provided storage key/digest is treated as report binary authority. Mitigation: validator requires the server-generated storage key/digest evidence boundary and forbidden evidence classes include client-provided storage metadata.
