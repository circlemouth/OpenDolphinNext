- Surface: `OrderDockPanel` existing bundle edit / copy / delete controls.

## Threat Model

- Asset: active patient order bundle operation context and visible blocked-operation reason.
- Trust boundary: browser UI is not an authorization boundary; server-side order mutation authority remains authoritative.
- Attack surface: missing patient context, read-only chart state, missing master data, fallback data, repeated clicks, and delete confirmation entry.

## Misuse Cases

- A user attempts to edit an existing order while master data is missing and receives only a silent disabled control.
- A user attempts to copy a fallback/read-only order bundle and opens the editor despite blocked prerequisites.
- A user attempts to delete a bundle from a blocked chart state and reaches delete confirmation without seeing the blocking reason.

## Implementation

- `OrderDockPanel` bundle edit/copy/delete controls now use `aria-disabled=true`, nearby `order-dock-edit-block-reason`, and push-time blocked notices for patient/read-only/master/fallback blockers.
- Bundle edit/copy exits before editor open when blocked.
- Bundle delete exits before delete confirmation when blocked; native `disabled` remains for mutation pending state.
