## Implementation

- Wired `/api/orca/official/reports/{type}` to save `orca_report_snapshot` after ORCA report parsing and fail closed if snapshot persistence is unavailable.
- Changed report audit details to store invoice/Data_Id presence and hash only, not raw values.

## Threats / Mitigations
- Misuse case 1: A client tries to make OpenDolphinNext the billing source by updating amounts locally. Mitigation: no local amount update API was added; cache rows are constrained to `source_system=ORCA` and fixed source APIs/statuses.
- Misuse case 2: Raw invoice number, insurance combination, or ORCA Data_Id leaks through cache/audit evidence. Mitigation: cache/snapshot summaries use hashes and presence flags; focused tests assert raw values are absent.
- Misuse case 3: ORCA returns success but cache/snapshot persistence fails, leaving an unverifiable display. Mitigation: resources return a sanitized 503 instead of a success response when persistence fails.
- Misuse case 4: Restore/outage flow promotes local billing/report snapshots to source of truth. Mitigation: outage runbook now requires ORCA re-fetch and forbids local snapshot promotion.
