# Iteration 20260510T110548Z

## Scope

- Checklist item: ORCA disease mirror read model must use explicit `baseMonth` instead of relying on implicit date fallback.
- Code surface: `web-client` Charts disease API and `DiagnosisEditPanel`.

## Changes

- `fetchDiseases` now sends `baseMonth=yyyyMM` to `/api/local/diagnoses/{patientId}`.
- `DiagnosisEditPanel` derives `baseMonth` from `meta.visitDate` and includes it in both the query key and the server request.
- Malformed client-side `baseMonth` input is not forwarded as authority; the API client falls back to the visit-date-derived month and the server remains the final validator.
- Updated UI current contract to document that Charts sends visit-date-derived `baseMonth` for the ORCA disease mirror.

## Security Notes

- Client input remains non-authoritative: facility, ORCA URL, owner, digest, raw query/XML, and storage keys are not sent.
- Misuse case: caller passes malformed `baseMonth`. Mitigation: web client drops malformed values, and server-side validation still rejects malformed direct requests.
- Misuse case: caller attempts to turn local-only disease into ORCA truth. Mitigation: the request only controls read-model base month; ORCA projection remains the sole `diseases` source.
