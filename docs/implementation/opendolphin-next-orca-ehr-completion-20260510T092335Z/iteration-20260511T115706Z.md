## Pre-implementation model

- Assets: ORCA transmission ledger, retry policy, idempotency keys, request hashes, sanitized operation summaries, `ORCA_UNKNOWN` recovery rows, outage/restore runbook.
- Trust boundary: browser clicks, retry triggers, restored local DB state, and external ORCA responses are untrusted until server-side ledger state and read-only ORCA re-fetch reconcile them.
- Attack surface: duplicate mutation from double click or retry, timeout classified as success, restore/restart replay that resends without ORCA re-fetch, and tracked evidence leaking raw ORCA or patient/insurance details.

## Misuse cases

1. A timeout path records `medicalmodv2` as successful without `tmedicalgetv2` re-fetch, hiding an `UNKNOWN` result.
2. A double click or browser retry sends the same mutation twice because release validation no longer runs idempotency tests.
3. After server restart or backup restore, a persisted local status is trusted as ORCA truth and automatically resent without `resendBlocked` / manual review.
