## Scope

Harden latest `orca_medical_candidate` preview binding from hash-only comparison to exact prescription source revision comparison. This iteration does not implement live `medicalmodv2` send, ORCA adapter behavior, post-send re-fetch, or reconciliation.

## Threat Model

- Assets: `orca_medical_candidate` snapshot, source prescription revision id, current prescription revision id, prescription content hash.
- Trust boundary: client can provide only `chartRevisionId` as a route segment; facility and current prescription state are resolved server-side.
- Attack surface: latest candidate preview response and downstream send-preparation display.

Misuse cases:

- A prescription is reissued or changed to a new revision with identical content hash, and the old candidate is still shown as sendable.
- Client attempts to rely on a fake digest or stale candidate id instead of the current prescription source revision.
- Current prescription revision is missing or no longer linked, but latest candidate preview remains sendable.
