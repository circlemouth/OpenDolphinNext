## Scope

One-heartbeat slice for checklist 11 / Phase 4: make the common `CriticalOperationConfirmDialog` action buttons carry an explicit DADS priority and 44px touch-target contract. This is UI/a11y hardening only. Authorization, persistence, ORCA transmission, accounting state, and audit enforcement remain server-side / owning workflow responsibilities.

## Assets, Trust Boundary, Attack Surface

- Assets: critical operation intent, cancel/confirm actions, button priority, touch target size, disabled affordance, patient identity already repeated in the dialog, and the distinction between UI confirmation and server-side enforcement.
- Trust boundary: browser DOM, CSS, button state, and class names are untrusted UI hints. They do not prove authority, persistence, ORCA state, or audit completion.
- Attack surface: accidental destructive confirmation due to small/ambiguous controls, assistive technology ambiguity around disabled controls, CSS regression that shrinks modal actions below DADS minimum, and documentation implying UI confirmation is sufficient enforcement.

## Misuse Cases

1. A touch user or keyboard/motor-impaired user accidentally confirms a critical operation because the action target is too small. Mitigation: common modal buttons now have a shared `critical-operation-confirm__button` selector with `min-height: 44px` and `min-width: 44px`, covered by a focused CSS-contract test.
2. A user confuses cancel and confirm priority in a high-risk modal. Mitigation: cancel uses `critical-operation-confirm__button--secondary`; confirm uses `critical-operation-confirm__button--primary`, with danger tone still changing the primary color.
3. A disabled critical action appears actionable or fires under assistive tech. Mitigation: native `disabled` remains in place, `aria-disabled` is mirrored when disabled, and the test keeps disabled behavior covered.
4. The presence of a confirmation modal is mistaken for authorization or audit enforcement. Mitigation: docs state this is only patient mix-up / misoperation reduction and server-side enforcement remains authoritative.
