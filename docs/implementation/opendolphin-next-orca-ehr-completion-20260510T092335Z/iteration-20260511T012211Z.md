## Threat Model

- Asset: active patient order recommendation apply context and visible blocked-operation reason.
- Trust boundary: browser UI is not an authorization boundary; server-side order mutation authority remains authoritative.
- Attack surface: missing patient context, read-only chart state, missing master data, fallback data, stale recommendation candidates, and modal-to-editor handoff.

## Misuse Cases

- A user applies a frequent-order recommendation while master data is missing and silently opens the editor.
- A user applies a recommendation in read-only/fallback state and mistakes the candidate as accepted for mutation.
- A stale patient context allows modal apply to dismiss the dialog and hide why order editing is blocked.

## Implementation

- `OrderDockPanel` recommendation apply now runs the shared push-time guard before resolving/opening the editor.
- Blocked apply shows `頻用オーダー反映を停止: ...`, does not open the editor, and keeps the recommendation modal visible.
- Candidate fetching and server-side order authority are unchanged.
