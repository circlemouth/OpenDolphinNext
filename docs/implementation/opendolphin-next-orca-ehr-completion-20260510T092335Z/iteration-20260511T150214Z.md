## Scope

One-heartbeat slice for checklist 11 / Phase 4: move Charts `署名確定解除` onto the common `CriticalOperationConfirmDialog`. This is a UI confirmation/a11y change only. Signature unlock authorization, revision/event history, re-sign requirements, and audit enforcement remain server-side chart workflow responsibilities.

## Assets, Trust Boundary, Attack Surface

- Assets: signature-lock state, patient ID, visit date, reception/appointment references, unlock intent, and follow-up re-sign guidance.
- Trust boundary: browser lock state, modal text, selected entry, and unlock button state are untrusted UI hints. The server remains authoritative for permission, history, immutable chart events, and audit.
- Attack surface: wrong-patient signature unlock, accidental unlock from a generic button, and users mistaking signature unlock for chart finalization, accounting completion, or server-side authorization.

## Misuse Cases

1. A user unlocks the wrong patient's signature state. Mitigation: the common alertdialog repeats patient ID, visit date, reception ID, and appointment ID.
2. A user treats the first prompt as execution. Mitigation: the existing two-step flow is preserved; callback execution occurs only after the final `解除を実行`.
3. A user interprets UI unlock as chart finalization/accounting state change. Mitigation: the modal summary states that it is not chart finalization or accounting completion, and docs keep enforcement on the server-side chart workflow.
