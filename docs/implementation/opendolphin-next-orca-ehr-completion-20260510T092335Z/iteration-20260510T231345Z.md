- Attack surface: disabled-only finish controls, patient/encounter context bypass, client-side use of `selectedEntry.id` as patient authority, and accidental finish hook execution when ORCA context is incomplete.

## Misuse Cases
- A clinician cannot discover why `診察終了して会計へ送信` is unavailable because the button is native disabled and only a title carries the reason.
- Missing ORCA master or encounter context executes the local finish hook and creates a false success state.
- A row id is treated as patient ID and the finish-send path proceeds without a confirmed patient.

## Implementation
- Changed Charts `診察終了して会計へ送信` so precheck failures use `aria-disabled=true`, `data-disabled-reason`, title, and `charts-actions-finish-guard` instead of native disabled.
- Kept native disabled for lock/running/read-only states where duplicate mutation or conflict prevention is required.
- Routed clicks with finish precheck failures through the existing fail-closed `handleAction('finish')` blocked path, showing a warning banner and avoiding `onAfterFinish` / ORCA transport.
- Updated existing ORCA send focused tests that still expected native disabled for precheck failures.
