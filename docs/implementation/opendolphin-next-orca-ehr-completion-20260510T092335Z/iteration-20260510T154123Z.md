## Implemented Scope

- Added the Reception recovery action `ORCA状態を再照合` to the ORCA transmission review list.
- The Web client posts only the `transmissionId` path to `POST /api/local/encounters/orca-transmissions/{transmissionId}/reconcile-temporary-medical`.
- The client model drops server response fields that are not allowlisted for the UI, including raw ORCA body, insurance identifiers, and `Medical_Uid` values.
- The Reception UI displays a sanitized reconciliation summary with matching row count and total row count, while preserving `needsUserReview` semantics.

## Threats And Mitigations

- Client-side authority injection: the UI sends only `transmissionId`; patient, facility, insurance combination, voucher, sequential, `Medical_Uid`, URL, and raw XML are not included in the request.
- Sensitive result leakage: the normalized response exposes `medicalUidPresent` but not the `Medical_Uid` value, insurance details, or raw ORCA response body.
- Unsafe success semantics: the action text and result copy state that reconciliation is for review and must not be treated as resend success or billing completion.
