## Scope
- Assets: OpenDolphinNext chart source-of-truth records, revision status, revision event ledger, document integrity contract.
- Trust boundary: browser/client chart payloads, legacy document rows, ORCA-derived context, and exported evidence are untrusted. Facility, owner, status, document key, digest, and revision chain are server-side authority.
- Attack surface: direct chart updates after finalization, forged revision status, forged content digest, owner/facility spoofing, event summary leakage.

## Misuse cases
- Client submits `status=FINAL` or `content_hash` directly to mark a mutable draft as finalized without server validation.
- Client reuses another facility's document key or legacy document ID to attach a revision to the wrong chart.
- A correction event stores raw patient detail, insurance detail, credential, Cookie, Authorization, CSRF token, or raw ORCA body in tracked evidence.
- A non-DRAFT revision is updated in place instead of creating an event/new revision, erasing the original text.
