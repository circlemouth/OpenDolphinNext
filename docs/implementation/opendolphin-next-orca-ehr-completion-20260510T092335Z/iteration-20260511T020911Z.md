## Assets / trust boundary / attack surface
- Assets: `exportSchemaVersion`, `exportHashAlgorithm`, `exportHash`, sanitized JSON export payload.
- Trust boundary: API output is server-generated, but verifiers may run outside the application and need explicit hash semantics.
- Attack surface: verifier using the wrong algorithm, future schema changes compared as if they were the same payload contract, ambiguous export hash material.

## Misuse cases
- A verifier assumes a different hash algorithm and accepts an unverifiable archive.
- A future export schema changes but old/new payloads are compared without version context.
- Hash metadata is changed outside the server but not covered by the hash material.

## Implementation
- Added `exportSchemaVersion` and `exportHashAlgorithm` to `ChartRevisionExportResponse`.
- `ChartRevisionExportService` now sets `exportSchemaVersion=1` and `exportHashAlgorithm=SHA-256`.
- Included schema version and algorithm in the server-side export hash material.
- Extended export focused test to assert the metadata is present.
