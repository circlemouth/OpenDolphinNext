## Assets / Trust Boundary / Attack Surface

- Assets: `encounter_projection`, ORCA `acceptlstv2` cache, ORCA acceptance identifiers, department / physician / insurance combination warning state, live readiness evidence.
- Trust boundary: ORCA acceptance identifiers and warning state are server-derived from authenticated request context, `encounter_projection`, and `orca_acceptance_cache`; browser-provided acceptance / department / physician / insurance fields remain untrusted.
- Attack surface: client identifier smuggling into billing/encounter state, ORCA cancellation deleting local workflow state, raw ORCA/PHI leakage in warning evidence, stale cache being displayed as current source.

## Misuse Cases

1. Client supplies acceptance / department / physician / insurance aliases to create a link that bypasses server context. Mitigation: link rows are generated from `encounter_projection` and ORCA cache only; DB constraint fixes `client_provided_identifiers_trusted=false`.
2. ORCA `acceptlstv2` no longer returns an acceptance and the cache event directly cancels/deletes the local encounter. Mitigation: cache refresh updates only `encounter_orca_acceptance_link.warning_status`; `encounter_projection.business_state` remains unchanged.
3. Diff warning exposes patient or insurance details. Mitigation: `changed_fields_json` stores field names only, raw sensitive fields are excluded by DB constraint and tests.
