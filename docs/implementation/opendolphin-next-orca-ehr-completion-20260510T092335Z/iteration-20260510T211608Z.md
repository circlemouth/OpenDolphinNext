## Queue Item
- E-02: common patient header staged rollout.

## Scope
- Assets: web-client patient identity header, Charts patient summary, UI current contract, workstream checklist/board.
- Trust boundary: browser display only. Patient identity, ORCA source, fetched/cache status, department, physician, insurance, and acceptance context remain server-derived or navigation context values; this UI does not become authority for ORCA send, chart finalization, or authorization.
- Attack surface: patient mix-up through missing header context, stale ORCA data hidden in compact UI, insurance/department/physician omitted before critical operations, and accidental exposure of raw ORCA identifiers beyond the accepted visible context.

## Misuse Cases
- A user opens Charts with fallback/local patient data and misses that ORCA canonical source is stale before billing send.
- A user proceeds with the wrong department, physician, or insurance combination because those fields are only present in a later confirmation or debug panel.
- A client-side state injection changes displayed insurance/department fields and a future flow treats that UI display as server authority.
- A compact or mobile layout hides ORCA stale/fallback status behind details, reducing patient safety warnings.
