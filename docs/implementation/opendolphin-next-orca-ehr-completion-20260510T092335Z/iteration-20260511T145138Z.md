## Assets, Trust Boundaries, Attack Surface

- Assets: live fullflow closeout evidence, medicalmodv2 request identity, selected visit row metadata, billing/report eligibility.
- Trust boundaries: browser UI, Playwright request/response capture, screenshots, HAR, raw network records, and DOM row text are diagnostic-only and not authority.
- Attack surface: fullflow failure paths that write raw browser/network artifacts, request XML retained as review evidence, selected visit row text carrying patient details, HAR flag accidentally enabled with sanitized mode, and summary markdown linking to forbidden artifact folders.

## Misuse Cases

1. `QA_SANITIZED_EVIDENCE_ONLY=1` fails before browser launch but still creates `network/`, `screenshots/`, `har/`, or `request-xml/` directories that later get staged.
2. `medicalmodv2` request XML is written and then treated as reviewer evidence instead of a local-only diagnostic artifact.
3. `selected-visit-row.json` stores raw patient row text such as name, memo, or patient detail from the DOM.
4. A HAR or screenshot flag is enabled together with sanitized mode and silently leaves browser artifacts in the closeout tree.

## Implementation

- `qa-fullflow-weborca.mjs` now treats `QA_SANITIZED_EVIDENCE_ONLY=1` as disabling browser artifacts, HAR recording, raw network JSON, request XML writes, and screenshot writes.
- Sanitized summaries omit evidence paths for `network/`, `screenshots/`, `har/`, and `request-xml/`.
- `handoff-state.json` is reduced to presence/status flags in sanitized mode.
- `selected-visit-row.json` is reduced to allowlisted presence/count fields and `patientIdMatched`, without raw row text.
- Added `fullflowSanitizedArtifactGuard.test.ts` to assert early failure under sanitized mode does not create forbidden artifact directories or print forbidden evidence paths.
- Updated release validation and checklist/board to keep fullflow/billing closeout unclaimed until a live rerun succeeds or produces a sanitized classified blocker.
