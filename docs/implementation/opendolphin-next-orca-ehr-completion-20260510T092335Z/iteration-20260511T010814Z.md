# Worker A Iteration 20260511T010814Z

## Scope

- Queue: A-10 billing-send client authority alias rejection.
- Checklist: 3.3, 6, 13.
- Assets: `CloseAndSendToBillingRequest`, `close-and-send-to-billing`, server-derived ORCA acceptance/department/physician/insurance context.
- Trust boundary: normal billing send may use only `idempotencyKey` and optional precheck flag from the client. Acceptance identifiers, department, physician, insurance, patient, facility, voucher, sequential, class code, URL, digest, and raw XML are server authority.
- Attack surface: forged acceptance aliases in JSON, forged department/physician context, client-supplied insurance combination, reaching encounter lookup with client authority fields present.

## Misuse Cases

- Client sends `acceptanceId` to fill a missing ORCA acceptance.
- Client sends `departmentCode` or `physicianCode` to override server-derived encounter context.
- Client sends an `insurance` alias not covered by `insuranceCombinationNumber`.
- Forbidden client authority fields reach encounter lookup or audit write-path checks.
