## Scope
- Queue: E-04 follow-on.

- Surface: `OrderDockPanel` search input and category select.

## Threat Model
- Asset: active chart order-entry context and patient-scoped order editing workflow.
- Trust boundary: browser UI state is advisory only; server-side authorization and validation remain authoritative.
- Attack surface: blocked edit states caused by missing patient context, read-only mode, missing master, fallback data, and confusing disabled controls.

## Misuse Cases
- A user sees a disabled order search input and cannot tell whether patient context, read-only state, or master sync is blocking the action.
- Assistive technology reaches the search controls without a related reason and presents the blocked state as unexplained.
- A future UI change removes the blocked reason while leaving native disabled controls in place.

## Implementation
- Kept search input and category select as native disabled when the control cannot accept interaction.
- Added nearby `order-dock-search-block-reason` with the same fail-closed edit reason used by other OrderDock actions.
- Connected both controls to the nearby reason with `aria-describedby`.
