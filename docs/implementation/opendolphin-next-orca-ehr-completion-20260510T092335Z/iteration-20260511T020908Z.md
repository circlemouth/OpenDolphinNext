## Trust Boundary
- Request body is not authority for temporary medical reconcile.
- Facility comes from the authenticated request context.
- Patient, visit date, department, and matching context come from saved transmission/snapshot data only.

## Attack Surface
- Forged request body attempting to override patient, facility, voucher, sequential, insurance combination, or `Medical_Uid`.
- Body-carried URL or raw XML attempting to alter ORCA transport.
- Audit/repository lookup reached before rejecting a body-bearing request.

## Misuse Cases
1. A caller supplies a different patient ID in the reconcile request body.
2. A caller supplies voucher, sequential, insurance combination, or `Medical_Uid` in the body to influence matching.
3. A caller supplies raw XML or a URL in the body to alter the ORCA request.
4. A rejected request leaves raw body contents or patient/insurance details in tracked evidence.

## Implementation
- `reconcileTemporaryMedical` now rejects requests with a non-empty body or non-identity transfer encoding before audit write-path checks, repository lookup, or ORCA transport.
- The existing saved snapshot-only `tmedicalgetv2` payload builder remains the authority for patient/date/department.
- Focused test verifies body-bearing reconcile requests stop before audit/repository interaction.
