## Pre-implementation model

- Assets: ORCA transport settings, ORCA API HTTP traffic, `OrcaTransport` / `OrcaHttpClient`, official wrapper resources, release gate scripts.
- Trust boundary: resource/service code and future helper additions are untrusted until CI confirms ORCA traffic still goes through the transport abstraction.
- Attack surface: direct JDK HTTP clients bypassing ORCA audit/sanitization, ad hoc ORCA endpoint URL construction in resource/service layers, live Trial evidence generated through an untracked communication path.

## Misuse cases

1. A resource constructs `HttpClient` / `HttpRequest` directly and sends to ORCA without `OrcaTransport`, bypassing audit and result classification.
2. A helper creates a one-off timeout/retry path outside `OrcaHttpClient`, making `UNKNOWN` / retry behavior inconsistent.
3. A future live Trial script or server support path treats push/master-update helper HTTP usage as ORCA API success evidence.
