## Checklist Item

- 16.4 DB障害時読み取り専用モード: 診療録下書き保存・revision mutation を監査ログ書き込み不可時に fail-closed にする。

## Threat Model

- 監査ログDBまたは hash chain head が read-only / unavailable のまま診療録本文・タイトル・添付参照・revision が永続化され、真正性と追跡可能性が欠落する。
- クライアントが保存 payload を再送しても、server-side audit write path の可用性確認前に chart write が進まないこと。
- エラー応答に DB 詳細、SQL、内部パス、患者詳細、ORCA credential を出さず、固定 `reasonCode` と `retryable` だけを返すこと。

## Changes

- `KarteDocumentWriteResource` の document add/update/title/delete 入口で `AuthoritativeAuditRepository.isWritePathAvailable()` を確認し、不可なら `audit_log_write_unavailable` / HTTP 503 で永続化前に停止する。
- `KarteRevisionResource` の revise / restore 入口で同じ fail-closed guard を実行する。
- document write / revision write の focused tests に audit write path unavailable regression を追加し、既存テストには明示的な audit availability mock を入れた。
- checklist に診療録 payload 書き込み経路の DB read-only guard 完了項目を追記した。
