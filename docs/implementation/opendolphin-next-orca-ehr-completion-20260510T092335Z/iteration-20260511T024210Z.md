## Assets And Trust Boundary

- Assets: handoff summary, operator live result summary, `orca_billing_cache`, `orca_report_snapshot`, storage upload status, report binary availability.
- Trust boundary: operator result wrapper does not execute live ORCA traffic and does not accept raw ORCA bodies, report bodies, patient identifiers, invoice numbers, `Data_Id`, `Medical_Uid`, storage keys/digests, credentials, or browser artifacts. It accepts only sanitized operator output and turns it into a normalized evidence record.
- Attack surface: operator-provided JSON, raw identifier key names, upload failure being misclassified as success, live result without a ready handoff, artifact capture flags/env.

## Implementation

- Added `web-client/scripts/qa-orca-billing-report-live-result.mjs`.
- Extended `orca-billing-report-live-profile-evidence.mjs` with operator result command validation and sanitized result classification.
- Result evidence requires a ready manual handoff, allowed outcome, `rawSensitiveFieldsExcluded=true`, ORCA source, request/response hash shape, non-negative row count, report snapshot hash/status fields, server-generated storage key/digest presence, and no raw-sensitive key names.
- Upload failure / expired storage / missing server-generated storage metadata blocks accepted evidence.
- Added focused test coverage for accepted sanitized operator result and raw identifier / raw network / upload failure rejection.
- Updated release-validation, ORCA connection contract, checklist, worker board, and this iteration doc.

## Misuse Cases And Mitigations

- Misuse case: operator result includes raw `Data_Id`, invoice number, patient identifier, storage key, or credential. Mitigation: key-name scanner rejects raw-sensitive keys before result is accepted.
- Misuse case: storage upload failure is treated as a valid report binary. Mitigation: `UPLOAD_FAILED` and `EXPIRED` produce blockers; missing server-generated storage key/digest presence also blocks.
- Misuse case: live result is recorded without a ready manual handoff. Mitigation: result wrapper requires `orca-billing-report-live-handoff-sanitized-manual-approval` and `readyForManualLiveExecution=true`.
- Misuse case: result evidence is treated as local billing/payment/report body authority. Mitigation: claim boundary states it is only sanitized ORCA-derived cache/snapshot evidence.
