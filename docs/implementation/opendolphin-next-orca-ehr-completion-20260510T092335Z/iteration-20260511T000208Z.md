# Worker E Iteration 20260511T000208Z

## Scope
- E-04 follow-on: expand push-time reasons to Diagnosis quick ORCA disease create controls.
- Checklist 11: `disabled` dependency reduction and visible missing requirement reasons.
- Assets: `DiagnosisEditPanel`, ORCA disease quick-create controls, DADS input contract tests, UI current contract, checklist/board evidence.
- Trust boundary: browser UI is a visibility and safety surface only. ORCA disease authority, patient/department/date validation, authorization, and disease mutation persistence remain server-side.
- Attack surface: disabled-only diagnosis controls, ORCA mirror unavailable hidden behind inert buttons, read-only bypass into confirm/mutation, and local-only disease fallback being mistaken for ORCA truth.

## Misuse Cases
- A clinician cannot learn why disease registration is unavailable because the quick-create buttons are native disabled.
- ORCA mirror unavailable still opens the confirmation dialog and implies disease registration can proceed.
- Read-only state is bypassed from the quick-create path and reaches `diseasev3` mutation.

## Implementation
- Kept input fields read-only/disabled when ORCA mutation is blocked, but changed quick disease create action buttons to use `aria-disabled=true` plus `diagnosis-mutation-block-reason` instead of native disabled for ORCA mirror unavailable/read-only reasons.
- Kept native disabled for ORCA mirror loading and mutation pending states where duplicate or premature operation prevention is required.
- Added a push-time blocked notice: `ORCA病名操作を停止: ...`.
- Routed blocked quick-create/form/confirm attempts away from confirm and mutation paths.
