# キリンカルテ order input field inventory

RUN_ID: `20260516T063301Z`

この記録は Chrome で表示中のキリンカルテ画面を副作用なしで観察したもの。`登録する`、保存、実施状態変更、会計/ORCA送信相当操作は押していない。患者識別情報、資格情報、raw network body は記録していない。

## 処方

| 領域 | 観察項目 |
| --- | --- |
| 導線 | `オーダー : 処方` モーダル。左に `処方症状` カテゴリ、中央に候補薬一覧、`オーダー内容へ反映する`、右/下に `オーダー内容` グリッド。 |
| 候補 | 症状カテゴリ選択後、候補薬一覧から選択してグリッドへ反映する思想。候補反映は入力行への反映であり、登録操作とは分離。 |
| グリッド列 | `RP` / `薬剤名称` / `薬剤量` / `成分量` / `その他` / `後発変更可否` / `薬剤コメント` / `用法` / `検索方法`。 |
| 薬剤行 | 例: RP1 `メサデルム軟膏0.1%`、`採用薬外`、薬剤量 `5 g`、成分量 `0 -`、その他 `0 -`、後発 `変更可能`、薬剤コメント `痒いところ`、用法 `1日2回`、検索方法 `外用`、日数 `0 日分`。 |
| 空行 | RP2 は薬剤名未入力、薬剤量/成分量/その他が `0 -`、後発 `変更可能`、用法 `未選択`、日数 `0 日分` の形で残る。 |
| 操作 | `+薬剤`、`+RP`、`クリア`、`日数一括変更`、`備考`、`医師コメント`、`登録する`。 |
| 安全上の示唆 | 入力グリッドへの反映と登録ボタンが分離されている。OpenDolphinNext ではさらに `保存`、`処方確定`、`ORCA送信`、`会計済み` を分離して維持する。 |

## 点滴・注射

| 領域 | 観察項目 |
| --- | --- |
| 導線 | `オーダー : 点滴・注射` モーダル。`オーダー内容` グリッドの下にコメント、投与経路、速度指定、点滴速度、実施情報が続く。 |
| グリッド列 | `薬剤・器材` / `薬剤量・数量` / `成分量` / `その他` / `コメント`。 |
| 薬剤行 | 例: `ソルラクト輸液 250mL`、数量 `1 袋`、成分量 `0 -`、その他 `250 mL`、コメント入力欄。 |
| 投与指示 | 投与経路の選択欄に `静脈点滴`。速度指定の選択欄に `速度指定`。点滴速度は数値入力 + 単位 `mL/h`。 |
| 実施情報 | `未処置` / `処置中` / `処置済`、`実施者コメント`、`実施者`、`オーダー実施日時` が表示される。今回は表示調査のみで、実施状態更新は対象外。 |
| 操作 | `+薬剤`、`クリア`、`登録する`。登録は未操作。 |
| 安全上の示唆 | 投与経路・速度は院内運用補助として入力面に見える。OpenDolphinNext v1 では `速度指定` と `点滴速度` を local-only とし、ORCA送信 payload/XML には出さない。 |

## 処置・検査・算定・セット/検索

今回の Chrome 画面では、既に開かれていた処方および点滴・注射モーダルの未保存データ破棄を避けるため、モーダルを閉じる追加操作は行っていない。実装では既存 OpenDolphinNext の category registry と master search / set / stamp 導線を使い、次を current contract とする。

| 対象 | OpenDolphinNext への反映方針 |
| --- | --- |
| 処置 | `処置 / 手術 / その他` の既存 subtype と classCode allowlist を維持し、候補反映後は `オーダー内容` グリッドで本体行・材料行・コメント行を編集する。 |
| 検査 | `検体/一般 / 生理 / 細菌 / 画像診断` の既存 sendability を維持。local-only / import-only の送信停止理由を隠さない。 |
| 算定 | `基本料 / 指導料` の既存 class meta と数量送信契約を維持し、単位・指示・院内補足は local-only とする。 |
| セット/オーダー検索 | 右オーダーペイン内の検索、ORCA入力セット、頻用、セット/スタンプを候補導線として扱う。候補反映は下書き反映であり、保存・処方確定・ORCA送信・会計済み扱いにしない。 |
